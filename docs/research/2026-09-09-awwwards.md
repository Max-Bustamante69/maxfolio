# Lens: Awwwards Sites of the Day/Month — research digest (maxfolio)

Scope: Awwwards.com "Elements" — the Portfolio, Personal, Developer, Agency, One-Page and
Data-Visualization listing tags — sampled across the last ~12 months of winners, evaluated for
maxfolio's four themes (Apple Clean, /luxury, /brutalist, /menu) and the two NEW themes the owner
wants (neumorphism/soft-UI, and a Persona-3-inspired game-UI aesthetic), plus every existing section
(hero, stat band, Now+marquee, Experience/Years, Process stepper, Shopify Work index, Gallery,
Manifesto, Projects index, Skills ledger, FAQ, Contact, Explore themes).

Method note: Awwwards' own listing pages (`/websites/portfolio/`, `/personal/`, `/developer/`,
`/agency/`, `/one-page/`, `/data-visualization/`) were crawled for `/sites/<slug>` detail-page links
(162 unique candidates cached), interleaved round-robin across all six categories, then each detail
page was opened to resolve its actual "Visit Site" outbound URL. The **first 28 sites that resolved
to a distinct live domain** (deduped, ~5 per category) were captured: one capped full-page screenshot
(≤6000px) plus two mid/lower-scroll viewport screenshots each, at 1440×900, via Playwright/Chromium.
A handful were then re-opened interactively (real browser, not just static screenshots) specifically
to observe motion/interaction that a static capture can't show — those are marked "(live-interaction
confirmed)" below.

## 2. Idea catalog (24 ideas)

### 1. Hover-reveal case-list validated + logo-wall band (sadumedia.com)
- **Look:** A stack of large-type project-name rows (no thumbnails visible at rest); a small pill tag above each name; presumably a hover/tap reveals a video preview in the gap. Below the list, a horizontal row of client/partner logos under "TRUSTED BY THE BEST."
- **Section:** Shopify Work index (validates the existing hover-capture-preview pattern) + a new "who we've built for" logo strip above/below it.
- **Sketch:** No change needed to the existing hover-preview mechanic; add a compact `<ul>` of store wordmarks/favicons at 40-60% opacity, `filter: grayscale(1)`, full color on hover — same treatment as the ticker-lens "logo-strip marquee" idea, but static (not scrolling) since only ~18 stores exist.
- **Perf/a11y:** Static logo row is free; keep `alt` text as the real store name.
- **Shot:** `sadumedia-com-full.png`.

### 2. Hardware-panel skin for dense controls (tinkon.zui.ooo)
- **Look:** An entire UI (sketch pad, 8 sample pads, pitch slider, transport controls) skinned as a physical hardware sampler: light warm-gray body, inset/beveled rectangular "screens" with soft inner shadow, colored physical-feeling buttons (P1-P8), a horizontal fader with a round cap thumb, monospace all-caps labels.
- **Section:** The direct visual language for the **neumorphism/soft-UI theme** — apply this exact bevel/inset vocabulary to the stat band, skills ledger (as "pads"), and Process stepper (as transport controls).
- **Sketch:** CSS soft-UI recipe: base surface `background: var(--surface)`, inset elements get `box-shadow: inset 3px 3px 6px var(--shadow-dark), inset -3px -3px 6px var(--shadow-light)`; raised elements (buttons) get the same shadow pair without `inset`; both use very low contrast between surface and background so the shadows do all the shape-reading work. Keep corner radii large and consistent (a defined `--radius-panel` token).
- **Perf/a11y:** Pure `box-shadow`, zero JS cost. Soft-UI's classic accessibility failure is low contrast between raised/inset states for low-vision users — pair every shadow-only affordance with a secondary cue (icon state change, label change), and verify contrast ratios against the design-system's minimum, not just against the neumorphic surface color.
- **Shot:** `tinkon-zui-ooo-full.png`.

### 3. Orbit-scattered feature cards around a connector diagram (orchid.security)
- **Look:** Instead of a grid, 5-6 small cards are positioned at irregular offsets (staggered x/y, slight rotation) around a faint central connecting-line diagram, as if orbiting a hub; a separate section below renders a literal 3-node flow diagram (box → connector line → box → connector line → box) for a "how it works" sequence.
- **Section:** Skills usage ledger or Process — "new ways to show dense info" as a non-grid cluster instead of neat rows.
- **Sketch:** Absolutely-position each card with `top`/`left` percentages hand-tuned (not CSS grid) inside a `position: relative` container sized to viewport; connect card centers with a single SVG `<path>` whose `d` is computed from each card's `getBoundingClientRect()` on mount/resize; animate stroke with `stroke-dashoffset` draw-on-scroll (reuses the house "self-drawing line" technique already used in Process).
- **Perf/a11y:** Recompute the SVG path only on resize (debounced), not on scroll; cards need a real DOM order matching reading order (visual scatter, not tab-order scatter) — set `tabindex`/DOM order to the logical sequence regardless of visual position.
- **Shot:** `orchid-security-full.png`.

### 4. AI-chat-assistant pill under the hero (dineshrevunuru.com)
- **Look:** A soft rounded pill banner directly under the hero: a small circular avatar icon (sound-wave glyph) + "Meet my best friend LOREM!" + a short description + an "Ask Lorem →" button on the right.
- **Section:** Contact section or right under the hero — an opt-in chat entry point framed as a named "sidekick" rather than a generic chatbot widget, which fits maxfolio's personality-forward voice.
- **Sketch:** A `<button>` styled pill that opens a chat panel (could be a simple FAQ-answering widget seeded from the existing FAQ content, no new backend required for v1); avatar uses a small looping CSS "sound wave" (3-4 bars animating `scaleY` with staggered delays) instead of a static icon.
- **Perf/a11y:** The pill itself is static/cheap; only load any chat-panel JS on interaction (code-split), not on page load. Name the assistant clearly as AI in the accessible label to avoid the WCAG/consumer-trust issue of an ambiguous "who am I talking to."
- **Shot:** `dineshrevunuru-com-full.png`.

### 5. Honest empty-state copy for NDA'd/undocumented work
- **Look:** No visual UI — a plain paragraph replacing what would normally be a screenshot: "Designed and prototyped for [clients]. This work is under NDA and stayed in development, so there are no screens to show and no numbers to claim. **The scope is the point.**"
- **Section:** Shopify Work index / case-study sheet, for any store or project where metrics or images can't be shown — directly satisfies maxfolio's absolute-honesty constraint (never invent metrics) while still reading as confident, not apologetic.
- **Sketch:** A copy pattern, not a component — a dedicated "scope-only" case-study card variant: bold client-type + role description, zero numbers, ending on a one-line reframe of why the constraint itself is the credibility signal.
- **Perf/a11y:** N/A — pure content.
- **Shot:** `dineshrevunuru-com-full.png`.

### 6. Literal-material footer easter egg (dineshrevunuru.com)
- **Look:** The footer background is filled edge-to-edge with a tiled bubble-wrap texture (rows of raised circular "bubbles" with specular highlight), captioned in tiny type "scroll on — the footer hides bubble wrap ;)".
- **Section:** Footer / Contact — a small, low-risk personality moment; could be swapped for something on-brand (grid paper, punch-card holes, a subtle circuit-trace pattern matching Process).
- **Sketch:** A repeating SVG or CSS `radial-gradient` tile (`background-image: radial-gradient(...); background-size: 28px 28px`) with a top-left highlight and bottom-right shadow per dot for the raised-bubble look; purely decorative, `aria-hidden="true"`.
- **Perf/a11y:** CSS-only, effectively free. Keep contrast of any overlaid footer text verified against the busiest part of the pattern.
- **Shot:** `dineshrevunuru-com-full.png`.

### 7. Chapter-numbered progress counter for long scrollytelling (consider.digital)
- **Look:** A small centered numeral + "x / total" counter floats mid-viewport through a very long narrative scroll, incrementing as new named sections ("It starts at the source." → "You tap a link." → "What a page is made of.") enter view.
- **Section:** The case-study sheet's anchor-nav (already planned as "editorial narrative" in-house) — this is a concrete, minimal version of the wayfinding it needs: just a numeral counter, no full progress bar.
- **Sketch:** `IntersectionObserver` on each named section (`threshold: 0.5`), updating a single `<span>{index}/{total}</span>` React state — far cheaper than a scroll-linked progress bar.
- **Perf/a11y:** One observer set, not a scroll listener — no rAF needed. Expose the same info to screen readers via an `aria-live="polite"` region updated on section change, throttled so it doesn't spam.
- **Shot:** `consider-digital-full.png`.

### 8. Ripple/caustic WebGL texture as ambient hero background (why.zero.university)
- **Look:** The entire hero background is a slow, real-time simulated water-caustic/ice-crack ripple texture in a single desaturated teal, filling the viewport behind minimal type.
- **Section:** An optional "ambient" hero variant for /luxury theme — a slow-moving generative background instead of a static gradient or photo.
- **Sketch:** A lightweight fragment shader (2-3 sine-wave octaves warping a UV grid, no external asset) via a `<canvas>` + raw WebGL or a tiny library; cap to `devicePixelRatio` ≤ 1.5 and pause the rAF loop via `IntersectionObserver` when the hero scrolls out of view.
- **Perf/a11y:** GPU-only cost while in view; hard-gate behind `prefers-reduced-motion` (freeze on a single static frame) and behind a capability check (skip entirely on low-end/`navigator.hardwareConcurrency` low or `save-data` header present).
- **Shot:** `why-zero-university-full.png`.

### 9. Section-headline color rotation (amp.framer.media)
- **Look:** Each major section's H2 cycles through a different accent color down the page (purple → teal → dark red → purple again) while everything else (body copy, background) stays neutral — a cheap way to make a long scroll feel varied without changing layout.
- **Section:** Any of maxfolio's stacked sections (Experience, Years, Process, Skills) as a subtle rhythm device.
- **Sketch:** A fixed ordered palette array; each `<section>` reads its index mod palette length and sets `--section-accent` as an inline custom property consumed by that section's heading color.
- **Perf/a11y:** Free (CSS custom properties only). Verify every accent in the rotation meets text contrast against the section's background in both light and dark theme variants before locking the palette.
- **Shot:** `amp-framer-media-full.png`.

### 10. Live-data widget cards instead of static feature icons (trylevel2.com)
- **Look:** Three feature cards, each containing a small **live-looking mini component** instead of an icon: a radial gauge with a win-rate percentage, a multi-line performance chart, and a share/collaborate mini-card with copyable link + social icons — each one a believable, real UI fragment rather than an illustration.
- **Section:** Skills usage ledger or Shopify-Work index summary cards — show a real mini-chart (e.g., a tiny sparkline of the actual stat-band numbers, or a radial "years active" gauge) instead of a static icon.
- **Sketch:** Reuse the house count-up/chart primitives already built for the stat band and case-study sheet charts, just sized down to card-width (120-160px) and simplified to 1 data series.
- **Perf/a11y:** These are real (not decorative) data — give each mini-chart a text alternative (`aria-label` stating the value) since a tiny SVG chart is not screen-reader legible on its own.
- **Shot:** `trylevel2-com-full.png`.

### 11. Halftone-dot texture over dramatic 3D/photo content (oumahi.art)
- **Look:** A coarse, visible halftone dot-screen (like a newspaper comic print) applied as a global overlay/filter across dark, dramatically-lit 3D renders — the dots get larger/denser in shadow areas and finer in highlights, exactly like offset-print halftone reproduction.
- **Section:** The **Persona-3 game-UI theme** — this is a direct, concrete implementation source for the "halftone" requirement in the brief.
- **Sketch:** A CSS `background-blend-mode` or SVG `<feTurbulence>`+`<feColorMatrix>` approach is unreliable for true halftone; the robust route is a small tiling halftone-dot PNG/SVG pattern (dot size varying by a coarse noise field, pre-generated once) applied via `mix-blend-mode: multiply` over image/video elements, or a canvas post-process pass (sample luminance per cell, draw a circle sized to darkness) run once per hero image at build/generation time rather than live per-frame.
- **Perf/a11y:** Do this at asset-generation time (baked into the image), not as a live per-frame filter — a live halftone shader on every hero image is unnecessary GPU cost for a static illustrative effect. Never apply halftone over body text.
- **Shot:** `oumahi-art-full.png`, `oumahi-art-scroll2.png`.

### 12. Live cursor-coordinate readout on a blueprint grid (illoca.unseen.co)
- **Look:** A fine cream/tan graph-paper grid fills the background; a small hand-written-style monospace label in the top-left corner continuously updates with the pointer's `X`/`Y` position ("X 419.17 / Y 856.66") as it moves — like a CAD tool's status bar.
- **Section:** Process stepper (already planned as a "FIG_0x blueprint bento" pattern in-house) — this is the exact cursor-chrome detail that sells the "engineer-coded" feel the brand wants.
- **Sketch:** A single `pointermove` listener (passive, throttled to rAF) updating two `<span>` values in a fixed-position corner label; only mount the listener while the Process section is in view (`IntersectionObserver` gate) so it isn't running for the whole page lifetime.
- **Perf/a11y:** Purely decorative/no-op for a11y — mark the readout `aria-hidden="true"` and `pointer-events: none`; disable entirely on touch devices (`@media (hover: hover) and (pointer: fine)`) since there's no persistent cursor to track.
- **Shot:** `illoca-unseen-co-full.png`, `illoca-unseen-co-scroll2.png`.

### 13. Two-tone riso-print illustration with handwritten margin notes (illoca.unseen.co)
- **Look:** A single-hue-plus-cream illustration style (cobalt blue + cream, high contrast, visible print-grain texture) for editorial scenes, paired with a small handwritten-font annotation label ("ARCHITECTURAL", underlined) floating beside the main headline like a designer's margin note.
- **Section:** Process stepper or a Manifesto-band supporting illustration.
- **Sketch:** Source or generate illustrations constrained to a 2-color palette + a grain/noise overlay (`mix-blend-mode: multiply` grain PNG at low opacity); margin notes use a distinct handwriting webfont at small size, always paired with a literal underline `<span>` for a "sticky note" feel, never as the primary reading text.
- **Perf/a11y:** One grain texture image reused everywhere (cached), not regenerated per element. Handwritten-font annotations must stay decorative/supplementary — never the sole carrier of essential information, since handwriting fonts often fail legibility checks at small sizes.

### 15. Giant type bisected by a rising 3D object (21hrs.space)
- **Look:** A huge embossed/metallic word ("MOON") sits behind a photoreal sphere whose horizon rises from the bottom of the viewport as you scroll, progressively occluding the lower half of the letters — the object visually "eclipses" the type. Flanking small caps metadata labels sit at the baseline ("Apollo 11" / "1969"), inside a thin corner-bracket frame with film grain.
- **Section:** The typographic hero — a dramatic scroll-triggered variant where a key visual (a product photo, a stat globe, a Shopify storefront screenshot) crests up from below the hero headline as the user starts scrolling.
- **Sketch:** Hero headline in a fixed/absolute layer behind a `motion.div` image layer; image's `translateY` is driven by `useScroll({ target: heroRef, offset: ['start start','end start'] })` mapped via `useTransform` from `100%` to `0%` over the hero's own scroll range (not the whole page) so it settles once, doesn't chase forever.
- **Perf/a11y:** `translateY` only (compositor-cheap); reserve this for ONE hero moment, not repeated per section (see Avoid list). Under reduced-motion, show the object already in its resting position with no scroll-tied movement.

### 16. Content-aware loader copy + ambient-sound opt-in (eclipses.bogachev.fr)

- **Perf/a11y:** Skip control must be one of the first focusable elements on the page (not buried) so keyboard/screen-reader users aren't forced through a decorative intro. No audio autoplay without a user gesture — this site's "starts on touch" phrasing is the correct pattern (WCAG 1.4.2 compliant by default-off).

### 17. Morphing organic "shape as data" scene transition (eclipses.bogachev.fr)
- **Look:** Between "chapters" of the data story, an irregular blob (looking like a bitten coin / eclipse shadow) morphs shape while a giant year numeral counts through history beneath it, before dissolving into the next chart view.
- **Section:** A scene-setting transition between Years-chart eras, or between Manifesto-band statements.
- **Sketch:** An SVG `<path>` with `d` interpolated between 4-6 hand-authored blob shapes via `framer-motion`'s `animate` on the `d` attribute (or a small morph helper), timed to a numeral count-up running in parallel via the same count-up primitive already used in the stat band.
- **Perf/a11y:** Path morphing between same-point-count paths is cheap; keep to short (1-2s) transitions, not persistent looping ambiance, and skip entirely under reduced-motion (jump straight to the end state).
- **Shot:** `eclipses-bogachev-fr-scroll2.png`.

### 18. Explorable 3D world with a named guide + "Classic Site" fallback (persona-studio.com)
- **Look:** The entire homepage is a drag-pan/zoom isometric 3D city; nav items ("About", "Work", "Services", "Contact") are rendered as buildings you click to travel to; a named character ("June, City Guide") pops a dialog box with quest-style copy and an accept/dismiss choice ("VISIT THE ABOUT BUILDING" / "NOT NOW" / "ON IT!"), with a visible progress counter (areas visited / achievements); an "Enter First-Person" mode toggle deepens immersion further; critically, a small persistent "← Classic Site" link offers an instant bail-out to a normal page.
- **Section:** The most direct, complete model for the **Persona-3 game-UI theme's own entry/landing moment** and for "Explore themes" as a section — not necessarily a literal 3D city, but the *pattern*: playful primary navigation + an in-character guide + visible progress + an explicit low-effort escape hatch.
- **Sketch:** A cheaper 2D translation for maxfolio: an illustrated "map" (isometric or flat) where each nav destination is a drawn location, hover/tap triggers a short guide-character speech-bubble ("→ Head to Years to see 5 years of shipped work"), a small always-visible "Classic view" toggle switches to the existing plain layout instantly (a CSS class swap / route param, not a full reload).
- **Perf/a11y:** The 3D/WebGL route is expensive and motion-heavy — only justified if maxfolio commits fully to the game-UI theme as an opt-in alternate route (which the brief already scopes as a new `/persona`-style theme, not the default). The escape hatch is the non-negotiable a11y/UX detail: never make the illustrated map the *only* way to navigate.
- **Shot:** `persona-studio-com-full.png` (plus live interaction notes above; the static crawl caught the pre-interaction default view, not the guide dialog).

### 19. Constellation/graph portfolio with category-color filter chips (nicoborja.com)
- **Look:** The whole site opens on a starfield; a central cluster of glowing "nebula" nodes represents all projects; filter chips along the top (NICO / AI / GROWTH / DATA / MÚSICA / SOUND), each with its own colored dot, ring/highlight the matching nodes when active; the person's name is set in huge tracked-out letters overlapping the node cluster; instructional copy states the interaction model plainly ("click an area to explore · click a project to preview"); a light/dark toggle sits top-right.

- **Sketch:** For a a11y-safe, lower-cost version: a static (not physics-simulated) SVG/Canvas node map with fixed hand-tuned positions per project, `<circle>` nodes sized by some real metric (e.g., years active or feature count), filter chips toggle a `data-category` attribute that drives opacity/scale via CSS rather than re-simulating positions; clicking a node opens the existing case-study sheet.
- **Perf/a11y:** Avoid a live force-directed physics simulation (expensive, and results are non-deterministic/hard to make accessible); a hand-placed static layout gets the visual metaphor at a fraction of the cost. Provide a plain list/table view as an equivalent alternative (this maps directly onto the already-planned "Grid/List Toggle" idea for the Shopify index) since a node graph is not screen-reader-navigable on its own.

### 20. Illustrated character physically wipes away the loading screen (huyml.co)
- **Look:** A hand-drawn, comic-style character (cap, striped shirt, straining posture with sweat drops) leans into a black panel and visibly **pushes it sideways across the screen** over several seconds, revealing the site underneath as the panel's edge sweeps past — a wipe-transition with a character actually performing the wipe, rather than a progress bar.
- **Section:** A signature loading/intro moment for maxfolio generally, and a strong option specifically for the **Persona-3 game-UI theme's "comic feel"** requirement (this character is drawn in exactly that flat-color, heavy-outline comic style).
- **Sketch:** Two layers: the real page content underneath, and an SVG/PNG illustrated character positioned at the leading edge of a full-viewport `<div>` colored panel; the panel's `clip-path: inset(0 <progress>% 0 0)` (or `transform: translateX`) animates from `0%` to `100%` tied to actual asset-load progress (or a fixed ~1.5-2.5s timer if there's nothing real to wait for), with the character's `<img>` `left` position locked to the panel's trailing edge so it always looks like it's pushing.
- **Perf/a11y:** Keep the character asset small (SVG or a single sprite, not a lottie/video) so it doesn't itself become the thing users wait for; cap the total loader duration low (≤1.5s typical case) and skip it outright for repeat visits in the same session (`sessionStorage` flag) so it's a first-impression flourish, not a recurring tax; always provide a way to skip/click-through it.

### 21. Media-collage cluster + dated editorial news rows + sticker-cutout photo (trevornoah.com)

- **Sketch:** (a) absolutely-positioned circular `<img>` thumbnails with slight random rotation (`--r: <fixed per-item deg>`), overlapping via negative margins, front-most on hover (`z-index` bump + `scale(1.06)`); (c) an SVG `<clipPath>` with a hand-drawn jagged-edge path (irregular polygon, not a perfect circle) applied via `clip-path: url(#sticker-edge)`, plus a 2-4px offset white "stroke" layer behind the photo to fake a die-cut sticker border.
- **Perf/a11y:** All still images, no motion cost beyond a hover scale; the collage cluster needs a real DOM reading order (`aria-label`"media gallery, N items") independent of its scattered visual placement, same caution as idea #3.
- **Shot:** `trevornoah-com-full.png`.

### 23. Glowing pixel/LED dot-matrix wordmark (milo.gg)

### 24. Routed right-angle "circuit-trace" line diagram for milestones (unitedcarriers.com)
- **Look:** A thick black line, drawn only in right angles (no curves), splits from a single vertical stem into two horizontal branches and back, connecting a central headline ("RELIABILITY AT EVERY MILESTONE") to small labeled milestone callouts on either side — reads like a PCB trace or a metro-map junction rather than a smooth connector.

- **Perf/a11y:** Same cost profile as any other SVG line-draw (cheap, `stroke-dashoffset` only); this is a strict layout variant of an existing pattern, so no new a11y surface beyond what Process already needs to satisfy.

## 3. Avoid list

- **3D/WebGL-only content with no static fallback.** `aquirin.com` and (initially) `mystella.me` rendered as near-blank pages in an automated/first-load capture — if a hero visual depends entirely on a canvas that takes several seconds or a user gesture to initialize, real visitors on slow connections see the same blank page. Every canvas/WebGL hero needs a real static poster frame shown until the canvas signals ready.
- **A playful/game navigation with no escape hatch.** Persona Studio and Undead Fish Studio both nail this by shipping "Classic Site" / a plain fallback alongside their game-like entry points — an explorable 3D city or an arcade title screen is a valid *alternate* theme, never the only way to reach content, and never without an immediately visible, keyboard-reachable way out.
- **Halftone/grain/texture applied over body text.** Every halftone or riso-grain example above (oumahi.art, illoca.unseen.co) confines the texture to imagery and illustration, never to paragraphs — texture over text is a recurring legibility complaint on design forums.
- **Loading-screen theater that repeats on every visit.** A character-driven wipe (huyml.co) or an arcade title screen (undead-fish.com) is charming once; forcing a returning visitor through the same multi-second intro every session is a top complaint in Awwwards-adjacent critique threads — gate any non-trivial intro behind a `sessionStorage`/`localStorage` "seen" flag and always offer Skip.
- **Scroll-tied 3D-object reveals used more than once per page.** The "object rises to bisect giant type" (21hrs.space) is striking specifically because it happens exactly once, in the hero. Repeating the same mechanic in every section (as a tempting way to reuse the code) reads as a gimmick rather than a signature moment — reserve big scroll-driven set-pieces for one or two places per page, not a running device.
- **Scattered/orbit layouts with scramble-order DOM.** Orchid.security's floating card cluster and Trevor Noah's media collage both look intentionally "scattered" but must keep real reading/tab order — a scatter layout that is *also* scrambled in the DOM breaks keyboard navigation and screen-reader flow silently; visual randomness and source order are two independent decisions.
- **Ambient audio or long unskippable intros without explicit, honest labeling.** eclipses.bogachev.fr's "MUSIC ON — starts on touch" is the correct pattern (no autoplay, clear label, easy toggle); anything that autoplays sound or blocks scrolling for more than ~2s without a visible Skip control is a hard WCAG and UX failure regardless of how good it looks in a showcase reel.
- **Physics-simulated node graphs as the only way to browse.** A true force-directed constellation (like nicoborja.com appears to be) is expensive to compute, non-deterministic to test, and effectively unusable for assistive tech — the earlier "Grid/List Toggle" idea already planned for the Shopify index is the correct pairing: ship the node-graph as a visual *option*, never the sole navigation.
- **Category-color-coding without a legend or text label.** Any node/chip system that relies on color alone to convey category (as a bare implementation of nicoborja.com's filter chips might) fails colorblind users — every color-coded chip needs a text label, not just a dot.
