# LENS: ab-vercel — sticky 1/3 traffic split on maxfolio (Vite SPA on Vercel)

Scope note: this lens is technical/infra, not visual. The digest format below is adapted
accordingly — "ideas" are implementation patterns/decisions, not animation references. All
facts below were read live from the sources on 2026-09-08; screenshots and raw text dumps
are saved under `refs3/ab-vercel/` (`_text/*.txt` has the full innerText per page).

**Headline finding**: Vercel's docs are mid-rename (checked live, not from stale training
knowledge). "Edge Middleware" → **"Routing Middleware"**; "Edge Config" → **"Global Config"**
(`@vercel/edge-config` → `@vercel/global-config`). Both still work under their old names but
new docs, new examples, and `vercel.json`'s `proxy` key use the new names. Do not write code
against "Edge Middleware/Edge Config" tutorials found elsewhere without checking they still
match current API shape.

**Second headline finding**: the **Flags SDK** (`flags-sdk.dev`, `@flags-sdk/vercel`) is
**Next.js and SvelteKit only** — it does not apply to maxfolio (Vite React SPA, no server
components). Build the split with plain Routing Middleware + cookies instead (framework-agnostic,
explicitly documented as "Other frameworks" in the middleware API docs).

**Third headline finding**: Vercel Web Analytics `track()` custom events — the natural way to
tag a contact-form conversion by variant — are **gated to Pro/Enterprise plans**. Free/Hobby
page-view analytics is unrestricted, but you cannot free-ride custom events. The plan below
gives a zero-cost Hobby-compatible substitute (a tiny serverless counter API on Upstash Redis's
free tier) plus the upgrade path if Max moves to Pro.

## 2. Catalog of implementation patterns (≥20)

Each entry: name — mechanism — where it serves the plan — sketch — perf/SEO/a11y — screenshot.

### A. Routing / bucketing core

**1. Deterministic SHA-256 cookie bucketing (not `Math.random()`)**
Mechanism: hash a sticky `ab_id` cookie value (minted once with `crypto.randomUUID()`) salted
with the experiment name, take the first 4 bytes of the digest as a `Uint32`, divide by
`0xffffffff` to get a `[0,1)` fraction, compare against cumulative weights to land in bucket
A/B/C. Same id always yields the same bucket — a `Math.random()`-per-request bucketer flips
users mid-session and silently invalidates every metric computed from the test.
Serves: the entire split (Apple Clean / soft-UI / Persona-3 variant selection).
Sketch: `lib/bucket.ts` (Web Crypto, runs identically in Edge and Node runtime):
```ts
export type Bucket = 'control' | 'soft-ui' | 'persona';
const WEIGHTS: [Bucket, number][] = [['control', 1/3], ['soft-ui', 1/3], ['persona', 1/3]];
export async function assignBucket(saltedId: string): Promise<Bucket> {
  const digest = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(saltedId));
  const frac = new DataView(digest).getUint32(0) / 0xffffffff;
  let acc = 0;
  for (const [name, w] of WEIGHTS) { acc += w; if (frac < acc) return name; }
  return WEIGHTS[WEIGHTS.length - 1][0];
}
```
Perf: microseconds, runs once per new visitor only (cached in cookie afterwards). A11y: n/a.
Screenshot: `21-edge-middleware-running-ab-full.png` (source article with the exact code + diagrams).

**2. `middleware.ts` at project root, "Other frameworks" signature**
Mechanism: plain `Request`/`Response` Web APIs (no `next/server` import) — this is the
documented code path for non-Next.js projects.
Serves: the whole split; this is the single file that decides + rewrites.
Sketch: `middleware.ts`
```ts
import { assignBucket, type Bucket } from './lib/bucket';
export const config = { matcher: ['/', '/index.html'] }; // scope to tested routes only
export default async function middleware(request: Request) {
  const cookies = request.headers.get('cookie') ?? '';
  const idMatch = /(?:^|;\s*)mf_ab_id=([^;]+)/.exec(cookies);
  const bkMatch = /(?:^|;\s*)mf_ab_bucket=([^;]+)/.exec(cookies);
  let id = idMatch?.[1];
  let bucket = bkMatch?.[1] as Bucket | undefined;
  const isNew = !id || !bucket;
  if (isNew) { id ??= crypto.randomUUID(); bucket = await assignBucket(`hero_theme_v1:${id}`); }
  const ua = request.headers.get('user-agent') ?? '';
  const isBot = /bot|crawl|spider|slurp|bingpreview/i.test(ua);
  const effectiveBucket: Bucket = isBot ? 'control' : bucket!;
  const url = new URL(request.url);
  url.pathname = effectiveBucket === 'control' ? '/index.html' : `/_variants/${effectiveBucket}/index.html`;
  const res = new Response(null, { status: 200, headers: { location: '' } }); // placeholder, use rewrite() helper from @vercel/functions in real code
  return res; // see pattern 3 for the actual rewrite() call
}
```
Perf: adds one Edge-network hop before the static asset is served (~sub-ms compute + no
extra network round trip since it runs at the same PoP).
Screenshot: `02-vercel-middleware-matcher-full.png` (the official "Other frameworks" tab).

**3. `rewrite()` helper from `@vercel/functions`, not a manual Response**
Mechanism: `import { rewrite } from '@vercel/functions'; return rewrite(new URL(path, request.url))`
— documented as the framework-agnostic way to rewrite in Routing Middleware.
Serves: keeps the user-visible URL as `/` for every bucket (critical for SEO — see §4).
Sketch: replace the placeholder in pattern 2 with:
```ts
import { rewrite } from '@vercel/functions';
...
const res = rewrite(new URL(url.pathname, request.url));
if (isNew) {
  res.headers.append('set-cookie', `mf_ab_id=${id}; Path=/; Max-Age=7776000; SameSite=Lax; Secure`);
  res.headers.append('set-cookie', `mf_ab_bucket=${bucket}; Path=/; Max-Age=7776000; SameSite=Lax; Secure`);
}
res.headers.set('vary', 'cookie');
return res;
```
SEO: `Vary: cookie` stops a shared CDN cache from leaking one visitor's variant to another.
Screenshot: `02-vercel-middleware-matcher-full.png`.

**4. Scope the `matcher` to tested routes only, never the whole site by regex-negation**
Mechanism: `config.matcher: ['/']` (or `['/', '/es', '/ja']` if the language routes are
separate paths) rather than the "match everything except assets" negative-lookahead pattern
copied from generic tutorials.
Serves: avoids re-running the bucketing/hash logic on every JS/CSS/image request, which would
burn Hobby Function invocations for no reason and could 404 if the matcher paths don't exist
as literal files.
Perf: keeps Routing Middleware invocations to ~1 per new page-load instead of one per asset.
Screenshot: `01-vercel-edge-middleware-full.png`.

**5. Bot/crawler exclusion pinned to `control`**
Mechanism: regex-test the `user-agent` header for `bot|crawl|spider|slurp` and force
`effectiveBucket = 'control'` regardless of the cookie-derived bucket, without ever setting
the split cookie for that request.
Serves: keeps what Googlebot/Bingbot see stable (same theme every crawl) instead of a random
walk between three visually different themes.
SEO: directly called out by Vercel's own guide (source #26): "you can also prevent bots or
search crawlers from hitting experiments."
Screenshot: `31-vercel-guide-ab-testing-full.png`.

### B. Static-shell strategy (how the 3 themes actually get served)

**6. Path A — single SPA bundle + inline blocking script (recommended for maxfolio)**
Mechanism: keep ONE `index.html`/JS bundle (current architecture — React Router client-side
nav across 4 existing theme routes already works this way). Middleware still buckets and sets
`mf_ab_bucket` cookie, but instead of rewriting to a different static file, it rewrites to the
SAME `index.html` with an injected response header `x-ab-bucket`. A tiny **inline, synchronous**
`<script>` at the very top of `<head>` (before any CSS/JS loads) reads `document.cookie` and
sets `document.documentElement.dataset.abTheme = bucket`, mirroring the "no dark-mode flash"
pattern used by `next-themes`/`use-color-scheme`. The app's root component reads
`document.documentElement.dataset.abTheme` on mount to pick which of the two NEW theme routes
(neumorphism / Persona-3) to render at `/`, falling back to the existing Apple Clean default
for `control`.
Serves: all three variants, zero extra Vite build complexity, no risk of the SPA-rewrite/Vite
multi-entry interaction bugs described in pattern 8.
Sketch: inline script in `index.html` `<head>`, before `<link>`/`<script>` tags:
```html
<script>
  (function () {
    var m = document.cookie.match(/(?:^|;\s*)mf_ab_bucket=([^;]+)/);
    document.documentElement.dataset.abTheme = m ? m[1] : 'control';
  })();
</script>
```
Perf: zero CLS (attribute is set before first paint, same trick as dark-mode); avoids a second
CSS bundle fetch triggered by variant routing.
A11y: unaffected; screen readers see final DOM state as normal.
Screenshot: n/a (architectural pattern, not captured from a live page — flagged as such).

**7. Path B — true multi-page Vite build with a variant-specific static shell (heavier, use only if the hero must be a genuinely different static HTML document for LCP reasons)**
Mechanism: `vite.config.ts` `build.rollupOptions.input` lists 3 HTML entries; middleware
`rewrite()`s `/` to `/_variants/soft-ui/index.html` or `/_variants/persona/index.html` for
non-control buckets, leaving control at the default `/index.html`.
Sketch: `vite.config.ts`
```ts
import { resolve } from 'node:path';
export default defineConfig({
  build: {
    rollupOptions: {
      input: {
        main: resolve(import.meta.dirname, 'index.html'),
        softUi: resolve(import.meta.dirname, 'variants/soft-ui/index.html'),
        persona: resolve(import.meta.dirname, 'variants/persona/index.html'),
      },
    },
  },
});
```
And in `vercel.json`, the SPA catch-all rewrite (pattern 9) must come AFTER the middleware
rewrite resolves — Routing Middleware always runs first, so this ordering is safe, but the
catch-all `"/(.*)" -> "/index.html"` regex must not swallow `/_variants/**` paths (scope it or
add an earlier explicit rewrite for `/_variants/(.*)$` → itself).
Perf: true separate static shells = best possible LCP per variant (no client-side theme-switch
flash at all) but 3x the prerendered HTML/CSS to maintain.
Screenshot: `28-vite-multipage-retry-full.png` (official Vite multi-page doc) and
`26-vercel-vite-framework-docs-full.png` (Vercel's SPA-rewrite + "use Multi-Page App mode for
production" recommendation).

**8. SPA deep-link rewrite must coexist with the middleware rewrite**
Mechanism: `vercel.json` needs the standard Vite-SPA fallback so client-side routes like
`/luxury`, `/brutalist`, `/menu` still resolve on hard refresh, in addition to whatever the
middleware does for `/`.
Sketch: `vercel.json`
```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}
```
Gotcha: if adopting Path B (pattern 7), this catch-all will also match `/_variants/soft-ui/...`
asset requests unless Vite emits those under a path this rewrite ignores (static files under
`/assets/**` are served before rewrites per Vercel's routing precedence — verify with
`vercel build` output locally before trusting it in prod).
Screenshot: `26-vercel-vite-framework-docs-full.png`.

**9. Never put the variant name in the address bar**
Mechanism: the rewrite target changes only what's *served*, never `window.location`. This is
explicit in the deep-dive article's "named pitfalls" list: "Putting the variant in the
user-visible URL. Pollutes analytics and lets users self-select."
Serves: keeps Google indexing exactly one URL (`https://www.maxfolio.dev/`) for the page under
test, sidestepping any duplicate-content question entirely.
Screenshot: `21-edge-middleware-running-ab-full.png`.

### C. Storage / config for the split itself

**10. Global Config (renamed Edge Config) as the single knob for split weights**
Mechanism: store `{"heroThemeSplit": {"control":0.34,"soft-ui":0.33,"persona":0.33}}` in a
Global Config store; middleware reads it with `@vercel/global-config`'s `get()` at ~sub-ms
P99 latency (no external DB round trip). Changing weights (e.g. to pause the Persona-3 arm
if it's clearly losing) needs no redeploy.
Sketch: `middleware.ts` addition:
```ts
import { get } from '@vercel/global-config';
const weights = (await get('heroThemeSplit')) ?? { control: 1/3, 'soft-ui': 1/3, persona: 1/3 };
```
Dashboard click path: Vercel dashboard → the maxfolio project → **Storage** tab → **Create
Database** → select **Global Config** → name it (e.g. `maxfolio-experiments`) → **Create**.
This auto-creates the `GLOBAL_CONFIG` env var and connects it to the project. Then **Items** →
add the JSON key/value → **Save Items**.
Perf: reads happen at the edge PoP, no added network hop, unlike a Postgres/Mongo call.
Screenshot: `03-vercel-edge-config-overview-full.png`, `04-vercel-edge-config-get-started-full.png`.

**11. Skip Global Config for v1 — hardcode weights, iterate via redeploy**
Mechanism: for a personal-portfolio scale project, a hardcoded `WEIGHTS` array committed to
git and changed via a normal `git push` is simpler than provisioning a store, and Vercel
preview deployments give you a safe place to sanity-check a weight change before it's live.
Serves: reduces the initial implementation surface to exactly one new file (`middleware.ts` +
`lib/bucket.ts`) and zero new dashboard provisioning steps.
Recommendation: start here; move to pattern 10 only if Max wants to tune weights without
waiting for CI/deploy (e.g. pausing a losing variant same-day).

### D. Conversion tracking (contact-request events) — the plan-critical section

**12. Native Web Analytics custom events (`track()`) — Pro/Enterprise only**
Mechanism: `import { track } from '@vercel/analytics'; track('contact_submit', { variant })`
client-side, or `@vercel/analytics/server` for a server-side track from a Function.
Blocker: source #8 states plainly "Custom Events are available on Enterprise and Pro plans" —
confirmed live, not assumed. If maxfolio is on Hobby today, this path is unavailable until
upgrade ($20/mo Pro minimum).
Screenshot: `08-vercel-analytics-custom-events-full.png`.

**13. Hobby-compatible substitute — a tiny Upstash Redis counter API (recommended)**
Mechanism: one serverless function increments two Redis counters per event
(`exp:hero_theme_v1:{bucket}:view` on first paint, `exp:hero_theme_v1:{bucket}:contact` on
contact-form submit), using Upstash's REST API (no TCP connection needed from an Edge/Node
function, works within Hobby's function limits).
Sketch: `/api/track.ts` (Node runtime function, works on Hobby per source #28):
```ts
export const config = { runtime: 'nodejs' };
export default async function handler(req: Request): Promise<Response> {
  if (req.method !== 'POST') return new Response('Method not allowed', { status: 405 });
  const { bucket, event } = await req.json(); // event: 'view' | 'contact'
  if (!['control','soft-ui','persona'].includes(bucket) || !['view','contact'].includes(event)) {
    return new Response('Bad request', { status: 400 });
  }
  const url = `${process.env.UPSTASH_REDIS_REST_URL}/incr/exp:hero_theme_v1:${bucket}:${event}`;
  await fetch(url, { headers: { Authorization: `Bearer ${process.env.UPSTASH_REDIS_REST_TOKEN}` } });
  return new Response(null, { status: 204 });
}
```
Client call sites: (a) once per session on first render, gated by a `sessionStorage` flag so a
page-reload doesn't double-count a "view"; (b) in the contact form's submit handler, alongside
whatever the form already does, reading `document.documentElement.dataset.abTheme` for `bucket`.
Dashboard click path: Vercel dashboard → maxfolio project → **Storage** → **Create Database**
→ **Marketplace Database Providers** → **Upstash** → **Redis** → pick the **Free** tier →
**Continue** → confirm project link. This auto-populates `UPSTASH_REDIS_REST_URL` and
`UPSTASH_REDIS_REST_TOKEN` env vars. Equivalent one-liner from the CLI: `vc i upstash`.
Perf/cost: free tier easily covers a low-traffic portfolio (Upstash free tier is
request-count-limited per day, not by data volume — verify the current numeric cap in the
Upstash dashboard at provisioning time since Vercel's marketplace page doesn't quote it).
Screenshot: `09-vercel-marketplace-upstash-full.png`.

**14. Minimal dashboard: a password-gated static page reading the counters**
Mechanism: a second function `/api/experiment-stats.ts` (GET) reads all 6 counters
(3 buckets × {view, contact}) from Upstash via `MGET`, computes conversion rate per bucket,
and returns JSON — gated by a shared-secret query param or header checked against an
`ADMIN_TOKEN` env var (Hobby has no built-in Password Protection — that's a Pro feature, see
below). A tiny static `admin.html` (not part of the public SPA bundle, just a flat file
outside `dist` or behind the same token) fetches that JSON and renders 3 numbers + a bar per
variant — no charting library needed at this scale.
Sketch:
```ts
// /api/experiment-stats.ts
export default async function handler(req: Request): Promise<Response> {
  if (req.headers.get('x-admin-token') !== process.env.ADMIN_TOKEN) {
    return new Response('Unauthorized', { status: 401 });
  }
  const buckets = ['control', 'soft-ui', 'persona'];
  const base = process.env.UPSTASH_REDIS_REST_URL;
  const headers = { Authorization: `Bearer ${process.env.UPSTASH_REDIS_REST_TOKEN}` };
  const results = await Promise.all(buckets.map(async (b) => {
    const [views, contacts] = await Promise.all([
      fetch(`${base}/get/exp:hero_theme_v1:${b}:view`, { headers }).then(r => r.json()),
      fetch(`${base}/get/exp:hero_theme_v1:${b}:contact`, { headers }).then(r => r.json()),
    ]);
    const v = Number(views.result ?? 0), c = Number(contacts.result ?? 0);
    return { bucket: b, views: v, contacts: c, rate: v ? c / v : 0 };
  }));
  return new Response(JSON.stringify(results), { headers: { 'content-type': 'application/json' } });
}
```
Alternative if Max upgrades to Pro later: swap this whole section for pattern 12 +
Vercel's built-in Web Analytics Events panel — no custom dashboard needed at all.

**15. Vercel Password Protection (Pro feature) as an alternative admin gate**
Mechanism: Project Settings → **Deployment Protection** → **Password Protection** — puts the
entire preview/prod deployment behind a password. Only worth it if Max is already on Pro for
other reasons; otherwise pattern 14's header-token check is the zero-cost equivalent for a
single admin-only endpoint.

**16. Cron-driven daily rollup (optional polish)**
Mechanism: `vercel.json` cron entry hitting `/api/rollup-daily` once a day, which snapshots
the current counters into a dated Redis key (`exp:hero_theme_v1:2026-09-08:control:view`) so
the dashboard can later show a day-by-day trend line, not just an all-time total.
Sketch: `vercel.json`
```json
{ "crons": [{ "path": "/api/rollup-daily", "schedule": "5 0 * * *" }] }
```
Confirmed free on all plans (source #10); timezone is always UTC, no `MON`/`JAN` aliases.
Screenshot: `10-vercel-cron-jobs-full.png`.

### E. SEO / cloaking safety

**17. No cloaking — bots and users see structurally equivalent content**
Mechanism: pattern 5 (bots always get `control`) already sidesteps most of this, but the
deeper rule is that even the two treatment arms (soft-UI, Persona-3) must be genuine design
skins over the *same* information architecture and copy meaning — not thin/spam variants —
so that whichever one a real crawl snapshot catches is still a faithful representation of the
site. This is longstanding, still-cited Google guidance (originating from a 2012 Webmaster
Central post on website testing) rather than a page fetched fresh this session — flagged
honestly as background knowledge, not a live citation.
Serves: keeps the whole exercise compliant even though it wasn't independently re-verified
via a live fetch this session (the specific 2012 post could not be located through search —
see the "avoid" list, item 3).

**18. Single canonical URL, no `rel=canonical` cross-linking needed**
Mechanism: because pattern 9 keeps every bucket at the same `https://www.maxfolio.dev/` URL
(rewrite, never redirect, never a query-param variant), there is no duplicate-URL situation to
canonicalize in the first place — simpler than the classic "variant B lives at `/b`" case that
`rel=canonical` guidance is written for.
Screenshot: `30-google-search-central-abtest-full.png` (general canonicalization background).

**19. If a redirect is ever used instead of a rewrite, it must be 302/temporary, never 301**

### F. Statistical honesty (the "absolute honesty" rule applied to sample size)

**20. Two-proportion sample-size math, computed here (not fetched from a single calculator)**
Formula (standard 80%-power, 95%-confidence rule-of-thumb): `n_per_arm ≈ 16 · p·(1−p) / d²`
where `p` is the baseline conversion rate and `d` is the absolute minimum detectable effect
(MDE). Contact-form submission on a portfolio is a **rare binary event**, which is the worst
case for sample-size math — small `p` makes `p·(1−p)` small but `d` (a realistic absolute lift)
is even smaller relative to `p`, so `n` explodes. Worked examples (Max should sanity-check the
actual baseline rate from current analytics rather than trust these placeholders):
- Baseline `p = 3%`, testing for a **50% relative lift** (3%→4.5%, `d = 1.5pp`):
  `n ≈ 16 · 0.03 · 0.97 / 0.015² ≈ 2,070 visits per arm`, **≈ 6,200 total** across 3 arms.
- Baseline `p = 3%`, testing for a **25% relative lift** (`d = 0.75pp`):
  `n ≈ 8,280 per arm`, **≈ 24,800 total**.
At **30 visits/day** site-wide (typical low-traffic personal portfolio order of magnitude —
Max should replace with his real number): 6,200 total visits takes **~7 months**; 24,800
takes **~2.3 years**. At **150 visits/day**: ~6 weeks and ~5.5 months respectively. At
**500 visits/day**: ~12 days and ~50 days respectively.
Honest conclusion for the digest: **a 1/3 split on a rare event like "contact request" is only
practical at meaningfully higher traffic than a typical solo portfolio gets, on any realistic
(30/60/90-day) timeline** — it can reliably catch a *large* effect (a variant that's clearly
much better or much worse) within 60–90 days at a few hundred visits/day, but cannot resolve a
subtle copy/color difference at low volume. Recommended framing to Max: run the test as a
**directional/qualitative signal** (which theme gets more scroll depth, more time-on-page, more
gallery interactions — a continuous/frequent metric, not just the rare contact-form binary),
and treat "did anyone convert at all in each arm" as a coarse tie-breaker rather than a
p<0.05 decision. Do not report a winner from this test with invented confidence — say plainly
if the sample size actually reached was below the number computed above.
No single online calculator is treated as canonical here (several exist —
samplesizecalculator.net, abtestplan.com, textkit.dev/sample-size-calculator, etc. — all
implement the same public formula); the number is derived directly rather than cited from one
vendor's tool, per the absolute-honesty rule.

## 3. Avoid list

1. **Do not build against "Edge Middleware"/"Edge Config" tutorials or blog posts without
   checking the current name/package** — Vercel silently renamed both this year
   (Routing Middleware, Global Config / `@vercel/global-config`); older community content
   (including the vercel/examples repo itself, still named `edge-middleware/...`) uses the old
   names and, in a few cases, old Next.js-specific `NextResponse.rewrite()` calls that need
   translating to the framework-agnostic `rewrite()` from `@vercel/functions` for a Vite app.
2. **Do not reach for the Flags SDK or the native "Vercel Flags" dashboard product** for this
   project — both are Next.js/SvelteKit-only, confirmed independently on two separate doc
   pages. A Vite SPA gets nothing from them; use plain Routing Middleware + cookies instead.
3. **Do not assume Web Analytics custom events are available** — they're Pro/Enterprise-gated
   (confirmed live). Don't design the measurement plan around `track()` without first checking
   which plan the maxfolio Vercel project is actually on.
4. **Do not bucket with `Math.random()` per request** — the single most-cited failure mode
   across sources (#18, #19, #21's underlying source, the community thread) is a user flipping
   variants between requests because the assignment isn't a pure function of a sticky id.
5. **Do not forget `Vary: cookie` (or fold the bucket into a synthetic cache key)** if any
   CDN-level caching sits in front of the rewritten response — a variant-blind cache key means
   "the first variant served becomes everyone's," a bug that looks like a broken experiment
   but is actually a caching bug.
6. **Do not put the variant name in the visible URL or query string** — pollutes analytics,
   lets users self-select by bookmarking, and turns a one-URL SEO story into a multi-URL one.
7. **Do not report a statistically confident winner from a low-traffic short test** — compute
   (or ask for) the real sample size needed for the real baseline conversion rate before
   claiming significance; a portfolio's contact-form conversion is a rare event and the math
   above shows it needs either high traffic or a long window.
8. **Do not treat forum/vendor blog code as gospel over official docs** — the ab-testing
   pattern found on independent sites (edge-middleware.com, rollgate.io) is technically solid
   and was used above, but every API call it makes (`rewrite`, `NextResponse`, matcher syntax)
   was cross-checked against the current official Routing Middleware API reference (#2) before
   being adapted for maxfolio's Vite context.
9. **Do not invent an Upstash free-tier request quota number** — the marketplace listing page
   didn't quote one; check the actual current limit in the Upstash dashboard at provisioning
   time rather than repeating a possibly-stale figure from memory.
