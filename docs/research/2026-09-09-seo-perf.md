## 2. What maxfolio does today (baseline, so the checklist below is diffs, not repeats)

- `index.html` already ships: title/description/keywords, canonical (`https://www.maxfolio.dev`), OG + Twitter card tags, **two** JSON-LD blocks (`Person`, `WebSite`), theme-color, a static localized hero shell for LCP, non-blocking Google Fonts + Fontshare loading, `sourcemap: true` in `vite.config.ts` for the Lighthouse Best-Practices audit.
- `src/components/common/SEOHead.tsx` mutates `<title>`, `description`, `og:*`, `twitter:*`, `canonical`, and optional `robots: noindex` **client-side in a `useEffect`** — it runs after React mounts, so it never appears in the raw HTML a non-JS-executing crawler fetches; each theme route (`Apple.tsx`, `Design1.tsx`/brutalist, `Design4.tsx`/luxury, `Home.tsx`/menu) calls it with its own title/description but **all four routes still emit the same `og-image.png`** — no visual distinction between an Apple/Luxury/Brutalist/Menu share card.
- `src/context/LanguageContext.tsx`: locale is **never in the URL** — it's `localStorage['lang']` + `navigator.language` sniffing, with `document.documentElement.lang` set client-side. There is **no hreflang anywhere** (correctly so, since hreflang requires distinct URLs per language and none exist). A crawler with no saved `localStorage` and a `navigator.language` of `en-US` (Googlebot's default) will only ever see the English copy — the ES and JA content is functionally invisible to search engines today.
- `public/robots.txt` points its `Sitemap:` line at `https://maxfolio.co/sitemap.xml`, but every canonical/OG/JSON-LD URL in `index.html` is `https://www.maxfolio.dev` — **a live mismatch**, not a hypothetical one (checklist item 1).
- `docs/lighthouse-baseline.md`: latest measured run is mobile 95/100/100/100, desktop 100/100/100/100, mobile LCP ≈2.7s, TBT 60ms, CLS 0, main chunk 140.7KB gz. This is the number any INP/content-visibility change below must not regress.
- No SSR/SSG/prerender plugin in `vite.config.ts` — pure client-rendered SPA. `react-router-dom`'s `BrowserRouter` means `/luxury`, `/brutalist`, `/menu` are client-side routes; a raw `curl` of any of those three paths on a static host returns the SPA shell for `/` unless `vercel.json`'s catch-all rewrite (`"source": "/(.*)", "destination": "/"`) is paired with per-route meta injected before hydration — today it isn't.

## 3. Checklist — concrete changes, each with the exact snippet

### 3.1 Fix the sitemap/canonical domain mismatch (ship this regardless of anything else)
**File:** `public/robots.txt`. The `Sitemap:` line names the wrong domain relative to every other canonical URL in the repo.
```
Sitemap: https://www.maxfolio.dev/sitemap.xml
```
Also add explicit disallow-none clarity and a host line is unnecessary (Google ignores `Host:`); just fix the domain and match `www.maxfolio.dev` exactly as `index.html` does (no bare `maxfolio.dev` redirect loop risk).
Perf/a11y notes: none — zero-risk text fix.

### 3.2 `Person` + `ProfilePage` JSON-LD (upgrade the existing `Person`+`WebSite` pair)
Keep the current `Person` block (it already matches schema.org's reference fields) and add `hasOccupation` for the CTO title's dated tenure, plus swap the plain `WebSite` for `ProfilePage` wrapping it as `mainEntity` — this is the structured-data shape Google's Profile-page rich result actually keys on:
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "ProfilePage",
  "url": "https://www.maxfolio.dev",
  "name": "Maxfolio",
  "inLanguage": ["en", "es", "ja"],
  "dateModified": "2026-09-08",
  "mainEntity": {
    "@type": "Person",
    "name": "Maximiliano Bustamante",
    "url": "https://www.maxfolio.dev",
    "image": "https://www.maxfolio.dev/og-image.png",
    "jobTitle": "CTO & Shopify Tech Lead",
    "hasOccupation": {
      "@type": "Occupation",
      "name": "CTO & Shopify Tech Lead",
      "occupationLocation": { "@type": "City", "name": "Medellín" }
    },
    "worksFor": { "@type": "Organization", "name": "Digitdeck", "url": "https://digitdeck.co" },
    "knowsAbout": ["Shopify", "Liquid", "Shopify Functions", "React", "Remix", "Conversion Rate Optimization"],
    "sameAs": [
      "https://www.linkedin.com/in/maximiliano-bustamante-998b77173/",
      "https://github.com/Max-Bustamante69"
    ]
  }
}
</script>
```
Perf notes: inline JSON-LD, zero runtime cost. A11y: none. Source: schema.org `ProfilePage`/`Person` (screenshots above).

### 3.3 `CreativeWork` per storefront case study (new — nothing like this exists yet)
For each of the 18 Shopify case-study sheets, emit one `CreativeWork` (or `CreativeWork` + `image: ImageObject`) block, ideally injected by the same route that renders the case-study sheet:
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "CreativeWork",
  "name": "TGB Digitdeck — Shopify storefront redesign",
  "creator": { "@type": "Person", "name": "Maximiliano Bustamante" },
  "about": "Shopify Plus storefront rebuild with GTM/Meta CAPI event tracking",
  "image": { "@type": "ImageObject", "url": "https://www.maxfolio.dev/gallery/tgb-hero.png", "width": 1600, "height": 1000 },
  "url": "https://www.maxfolio.dev/#tgb"
}
</script>
```
This only pays off once each case study has its own crawlable URL/anchor (today they're all client-rendered on `/` via history-pushed sheet state) — see 3.5 for why that needs prerendering to actually get indexed.

### 3.4 hreflang — the real gap (currently zero infrastructure for this)
Google requires **distinct URLs** per language to use `hreflang`; maxfolio has none (locale lives only in `localStorage`). Minimum viable fix without a full route rewrite: add `?lang=es` / `?lang=ja` as real, linkable, bookmarkable query-param routes that `LanguageContext` also reads on mount (in addition to `localStorage`), then declare them:
```html
<link rel="alternate" hreflang="en" href="https://www.maxfolio.dev/" />
<link rel="alternate" hreflang="es" href="https://www.maxfolio.dev/?lang=es" />
<link rel="alternate" hreflang="ja" href="https://www.maxfolio.dev/?lang=ja" />
<link rel="alternate" hreflang="x-default" href="https://www.maxfolio.dev/" />
```
And in `src/context/LanguageContext.tsx`, read `?lang=` before `localStorage`:
```ts
const params = new URLSearchParams(window.location.search)
const urlLang = params.get('lang')
if (urlLang && supportedLocales.includes(urlLang as Locale)) return urlLang as Locale
```
Caveat to be honest about: query-param hreflang is the weaker of Google's supported patterns (path-prefix `/es/` is preferred and what Search Central recommends), and this only fully works once each language's meta/JSON-LD is also emitted server-side per URL — see 3.5. Ship the query-param version now as the cheap fix; note path-prefix routing as the "do it properly" follow-up if the owner wants to invest in it. Source: standard hreflang mechanism (GSC's own hreflang doc was unreachable from this sandbox — see Avoid list — but the `rel=alternate hreflang` tag semantics are a stable, long-unchanged part of the spec, not something requiring a fresh citation).

### 3.5 Prerender per-route, per-locale HTML (the fix that makes 3.3 and 3.4 actually indexable)
`vite.config.ts` has no SSG plugin. Two Vercel-native options that don't require an SSR rewrite of the React app:
- **`vite-plugin-ssg`** (community) or **`vite-plugin-prerender-spa`**: crawl the built SPA with a headless browser at build time and write static HTML per route (`/`, `/luxury`, `/brutalist`, `/menu`, and `/?lang=es` etc. as separate output files) — each gets its own `<title>`/meta baked in, so `SEOHead.tsx`'s client mutation becomes a hydration no-op instead of the only meta a crawler ever sees.
- **Vercel's own static-generation path**: since this is a Vite app (not Next.js), Vercel doesn't auto-prerender it — the prerender step has to happen at build time via one of the plugins above, then `vercel.json`'s catch-all rewrite is narrowed to only the client-side sub-routes that don't have a static file.
Minimal `vite.config.ts` shape once a plugin is chosen:
```ts
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'
import prerender from 'vite-plugin-prerender-spa' // pick one, verify actively maintained before installing

export default defineConfig({
  plugins: [react(), prerender({ routes: ['/', '/luxury', '/brutalist', '/menu'] })],
  build: { sourcemap: true },
})
```
Perf notes: this is a build-time cost only — zero runtime JS added, and it can only *help* LCP/INP since the first paint becomes real HTML instead of the current static-shell approximation. A11y: none.

### 3.6 Per-theme OG image via `@vercel/og` (replace the single shared `og-image.png`)
Today `Apple.tsx`/`Design1.tsx`/`Design4.tsx`/`Home.tsx` all pass no `ogImage` override to `SEOHead`, so all four themes share one static PNG. Add a Vercel Edge Function:
```tsx
// api/og.tsx
import { ImageResponse } from '@vercel/og'
export const config = { runtime: 'edge' }
export default function handler(req: Request) {
  const { searchParams } = new URL(req.url)
  const theme = searchParams.get('theme') ?? 'apple' // apple | luxury | brutalist | menu
  return new ImageResponse(<ThemeCard theme={theme} />, { width: 1200, height: 630 })
}
```
Then each route's `SEOHead` call passes `ogImage={`https://www.maxfolio.dev/api/og?theme=luxury`}`. `@vercel/og` auto-sets CDN cache headers, so this is free at request volume. Source: Vercel `@vercel/og` docs (screenshot above).

### 3.7 `content-visibility: auto` on the long sections (Years / Gallery / Projects / Skills ledger)
```css
.years-scrubber, .gallery-strip, .projects-index, .skills-ledger {
  content-visibility: auto;
  contain-intrinsic-size: 0 1200px; /* measure each section's real collapsed height and use that, not a guess */
}
```
Measured elsewhere (web.dev's own demo): 7x rendering boost on initial load for long, mostly off-screen content — directly applicable since Years/Gallery are the longest, most image-dense sections in the current build. Must pair with an accurate `contain-intrinsic-size` (a wrong guess causes visible layout jump on scroll-into-view — the CLS regression risk to test against the `docs/lighthouse-baseline.md` CLS-0 baseline).

### 3.8 INP budget for the ticker/parallax work the owner asked for
Since the ask is explicitly "more animation, more parallax, ticker hover effects," every new scroll-linked or hover-linked handler needs to stay under web.dev's **200ms p75 INP** budget:
- Any marquee/ticker hover effect: transform/opacity only (compositor thread), never re-render React state on every `pointermove` — use a ref + direct style mutation or a Motion `useMotionValue`, not `useState`.
- Any new Lenis-driven parallax: read scroll progress via Lenis's own RAF callback (already the pattern for the existing self-drawing Process stepper), never a scroll listener that triggers React re-renders per frame.
- Test method: Chrome DevTools Performance panel → Interactions track, confirm each new hover/scroll handler resolves under 200ms, not just "feels smooth" — per **Lighthouse mide mi CPU, no la tienda** (house memory), always benchmark on an idle machine, never while another build/job is running.

### 3.9 `prefers-reduced-motion` coverage for every NEW animation (ticker, parallax, cut-in panels, halftone reveals)
```css
@media (prefers-reduced-motion: reduce) {
  .ticker-track { animation: none; transform: none; }
  .parallax-layer { transform: none !important; }
}
```
```tsx
// framer-motion equivalent, since maxfolio is on framer-motion not raw CSS animation for most motion
import { useReducedMotion } from 'framer-motion'
const shouldReduceMotion = useReducedMotion()
<motion.div animate={shouldReduceMotion ? {} : { x: [0, -200] }} />
```
Any scroll-hijacked panel (e.g. a future Persona-3-style "cut-in" panel that swaps to a static stacked layout under reduced motion) must also get `inert` on the now-hidden interactive variant, not just `display:none`, so it drops out of the tab/AT order — per web.dev's `inert` article (screenshot above).

### 3.10 Font-loading hygiene for the two NEW themes (neumorphism, Persona-3-style)
Whatever typefaces the two new themes add, follow the existing repo pattern exactly (already correct): `media="print" onload="this.media='all'"` non-blocking `<link>` + `<noscript>` fallback + `rel="preconnect"` to the font host. Add `font-display: swap` if either new theme self-hosts a variable font file instead of loading from Google Fonts/Fontshare, and preload only the single most-used weight/style actually visible in the first viewport of that theme's route:
```html
<link rel="preload" href="/fonts/persona-display-var.woff2" as="font" type="font/woff2" crossorigin />
```
Never preload a font for a theme that isn't the current route — `/menu`'s explore-themes index should not eagerly preload all six themes' fonts.

### 3.11 `will-change` hygiene
Given the amount of new motion being requested, audit that `will-change` is applied only to elements mid-animation and removed after (framer-motion manages this automatically for `motion.*` components via `layout`/`animate`, but any hand-rolled CSS parallax layer needs `will-change: transform` added on interaction start and removed on interaction end, not left on statically — a static `will-change` on many long-lived layers is the most common Lighthouse "avoid excessive DOM" / high-GPU-memory antipattern flagged in animated-site case studies).

### 3.12 Canonical under the planned A/B test
Once the 1/3 traffic A/B test ships (per the brief), whichever variant is NOT the canonical URL must self-referentially canonicalize to the single canonical URL (`https://www.maxfolio.dev/`) rather than each variant declaring itself canonical — otherwise Google may index and rank the wrong variant, or split signals across variants. This is the standard, uncontroversial A/B-test SEO pattern (not requiring a fresh citation) and is a one-line fix in `SEOHead`'s existing `canonical` prop: pass the same canonical value regardless of which A/B bucket rendered the page.

### 3.13 Sitemap: add `lastmod` accuracy + the case-study anchors once 3.5 lands
Once per-case-study URLs exist (3.3/3.5), add them to `public/sitemap.xml` with real `lastmod` dates (today's four entries already do this correctly — just keep it current, don't let `lastmod` go stale relative to actual content edits, which is a "why isn't this being recrawled" cause).

## 4. Avoid list (what forums/judges/Google itself criticize)

- **"AI slop" pages**: thin, keyword-stuffed, or auto-generated-feeling copy with no unique point of view — the opposite of what an owner-authored, honest-metrics portfolio should read like. Google's own guidance (paraphrased, not quoted) rewards demonstrated first-hand expertise; a portfolio site's advantage is that it's inherently first-hand.
- **hreflang without matching content parity**: don't declare `hreflang="ja"` pointing at a URL whose actual rendered content is still English because the query-param routing (3.4) wasn't wired into the initial render — that's a well-known hreflang misconfiguration Search Central flags (return-tag mismatch / wrong-language-at-URL).
- **Claiming a Google Search Central citation without being able to verify it live**: `developers.google.com` was unreachable from this sandbox for all three targeted pages (JS-SEO basics, Profile-page structured data, hreflang) — this digest substitutes web.dev's own rendering article and stable, long-unchanged hreflang/schema mechanics instead of asserting a page was read when it wasn't. Don't paper over a failed fetch by citing it anyway.
- **`will-change` left on everything**: several animated-site postmortems (referenced generically, not one specific forum thread — treat as a pattern, not a citation) call out permanently-set `will-change` across many layers as a GPU-memory/battery drain that shows up as jank on lower-end mobile devices specifically, which is exactly maxfolio's stated mobile-first priority.
- **Reduced-motion as an afterthought**: bolting on one blanket `@media (prefers-reduced-motion)` block that just disables everything, rather than providing an intentional static alternative per new animated section (ticker, parallax, cut-in panel) — the flat "just turn it off" approach reads as compliance-only, not design.
- **Prerendering that only fixes the default route**: shipping SSG for `/` but leaving `/luxury`, `/brutalist`, `/menu` and the locale variants client-only defeats most of the SEO value — the case-study/CreativeWork markup (3.3) and hreflang (3.4) are both gated on ALL routes being prerendered, not just the homepage.
- **A query-param-only hreflang as a permanent solution**: acceptable as the cheap first fix (3.4) but path-prefix locale routing (`/es/`, `/ja/`) is what Google's own documentation prefers when it can be reached to verify: flagged as a follow-up, not sold as the final state.
