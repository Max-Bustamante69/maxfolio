## 2. Idea catalog (≥20)

1. **Numbered story cards (Pudding index)** — Shopify Work index / Projects index. Each project gets a `#NNN`-style badge, a flat color field unique to that store (derived from its dominant brand color), a small custom illustration/screenshot, title + one-line dek + date. Grid, 3-up desktop / 1-up mobile. framer-motion: `whileHover={{ y: -4 }}`, stagger children on scroll into view with `viewport={{ once: true }}`. Perf: color fields are CSS, illustrations lazy-loaded; a11y: card is a single `<a>`, title as heading.
2. **Chart-type thumbnail wall (Observable Explore)** — could become a literal "How I show my work" mini-gallery in the FAQ or an about-the-site easter egg: small multiples of the chart types used across the site (unit chart, sunburst, calendar), each thumbnail linking/scrolling to where it's used live. Reinforces the site's own dataviz literacy.
3. **Radial tree / sunburst for skill hierarchy** — Skills usage ledger reimagined as a zoomable sunburst: center = "Max", ring 1 = category (Frontend/Shopify/Platform/AI), ring 2 = individual tech, arc length = frequency of use across the 18-store fleet (derived from actual `package.json`/theme-settings greps, never invented). SVG `<path>` arcs via d3-shape math (no need for full d3 runtime — precompute arcs at build time in a Node script, ship static SVG + a few event listeners). Motion: arcs draw in with `stroke-dashoffset` on scroll-into-view. A11y: each arc gets a `<title>` and the ring doubles as a `<table>` in a visually-hidden fallback.
4. **Calendar heatmap of build activity** — GitHub-contribution-style grid (7×52 cells) built from real commit dates across store repos, color intensity = commits that day. Placed under "Years" as a literal receipt of the "one block per shipped project" claim, or as a hover-reveal under the stat band. CSS grid of `<div>`s, color via CSS custom property bucketed into 5 steps (never smooth-interpolated — keeps it legible and matches existing token system). Cheap: one `<div>` per day × years, no canvas needed at this scale (~1825 cells).
5. **Streamgraph of stack usage over time** — years on the x-axis, stacked flowing bands = which frameworks/tools were in active use each year (React, Liquid, Remix, Tailwind versions, etc.), band thickness = number of stores on that stack that year. Good for "Skills usage ledger" turned longitudinal. Implementation: precompute band paths as smooth cubic splines at build time (small dataset, ~5 techs × ~6 years), render as static SVG, framer-motion path-morph on route enter using `animate` on the `d` attribute (or crossfade two static SVGs if path morphing proves jittery). Accessibility: pair with a hidden data table; never rely on hue alone (label each band directly on hover/tap).
6. **Radial/petal chart per store (OECD Better Life pattern)** — one small "flower" per store where petal length = a metric (Lighthouse score, features shipped, industry tags, tenure). Good as a hover-reveal on the Shopify Work index cards instead of a plain screenshot thumbnail — turns 18 similar-looking ecommerce screenshots into 18 visually distinct little glyphs. Precompute as static inline SVG per card (cheap: <20 nodes each), CSS `transform: scale()` on hover, `prefers-reduced-motion` guard to disable the scale.
7. **Diagonal split "fix my chart"-style before/after card (Datawrapper)** — reuse the diagonal-cut two-image card for a "before Digitdeck / after Digitdeck" or "old stack / current stack" moment in the Process stepper or a case-study sheet. CSS `clip-path: polygon(...)` on two absolutely-stacked images, label chips top-left/bottom-right. Cheap, no JS needed beyond an optional hover-to-slide the clip-path percentage with `framer-motion`'s `useMotionValue` bound to pointer x.
8. **Annual-report hero stat (Octoverse pattern)** — one giant, editorialized headline number as the FIRST thing in a section, not a chart at all: e.g. "A new store shipped every N weeks" framed exactly like Octoverse's "a new developer joins GitHub every second." This is a copy pattern more than a chart pattern — pairs with the existing count-up numerals in the stat band but leads with the *sentence*, chart second. Gradient/nebula background behind the headline via a static CSS conic/radial gradient (no WebGL needed — Octoverse's is CSS+SVG noise).
9. **Marquee-over-manifesto (Giorgia Lupi pattern)** — a thin horizontal ticker band directly above a huge centered pull-quote paragraph. Distinct from the existing "Now pill + marquee ticker" section — this is a *second*, smaller-scale use of marquee as a decorative rule above a big statement, good for the Manifesto inverted band. CSS `@keyframes marquee` translateX loop, `will-change: transform`, pause on hover/focus, respect `prefers-reduced-motion` (swap to a static repeated row).
10. **Hand-drawn micro-icons as nav labels (Mona Chalabi pattern)** — replace 2-3 header nav words with small custom line-icon glyphs beside the label (not instead of — accessibility). Evokes the hand-illustrated feel without literally copying anyone's art; icons drawn as simple single-stroke SVG paths, `stroke-dasharray` draw-in on first load.
11. **Bump chart of tech/role ranking per year** — years on x-axis, ranked lines for "primary role that year" or "most-used framework that year" crossing over as rank changes (classic bump chart). Good for Experience section as a longitudinal companion to the role rail. Data needed: one ranking array per year (role emphasis, or stack), small enough to hardcode from real history. SVG `<path>` per rank-line with `stroke-linecap: round`, labels at line ends only (no legend clutter).
12. **Waffle / unit chart for fleet composition** — 18 stores as an 18-square (or 6×3) waffle grid, each square colored by industry/category or by build-status (live/DEV/in-progress), tappable to reveal the store name+link. Distinct from the existing "Years" unit chart (which is per-project-per-year); this one is a single all-time census. CSS grid, each cell a `<button>`, color from a small fixed categorical palette (never more than ~6 hues), legend as a horizontal key row underneath.
13. **Subway-map timeline for the career line** — a single bent/right-angle "line" (like a metro map) running through the page, with "stations" = roles/milestones, "interchanges" = years two things overlapped (e.g. freelance + full-time). Alternative treatment for Experience if the "role rail + panel" split ever needs a v2. SVG path with right-angle turns (`M`/`L` commands only, no curves — keeps the metro-map honesty), station dots as small circles with `<title>` tooltips.
14. **Small multiples grid of store screenshots with one shared metric bar** — instead of a hover-capture preview per case study, show all 18 as uniform small thumbnails in a fixed grid, each with an identical thin metric bar underneath (e.g. relative AOV lift, or "sections built" count) so the eye compares bar lengths, not just images. Classic small-multiples discipline: same scale, same chart type, repeated — the "honest" alternative to one flashy chart.
15. **Dot-matrix stack map** — a grid of small dots, one per technology/skill, positioned by two axes (e.g. x = frontend↔backend, y = years of experience), sized/colored by frequency of use. A more information-dense alternative to a tag cloud for the Skills ledger. Precompute positions at build time from a hardcoded skills table (never invented numbers — frequency = literal count of stores/projects using that tech).
16. **Sankey-lite: role → skill flow** — a simplified 2-column sankey (not a full d3-sankey runtime) showing how a small number of roles (freelance / agency-CTO / etc.) connect to the skill clusters they used, band width = rough time allocation. Given only 2 columns this can be hand-built with straight/bezier `<path>`s rather than a library — keeps bundle size at zero.
17. **Seasonal/radial spiral for "Years" (Observable "Seasonal Spirals" pattern)** — instead of (or alongside) the current phone-scrubber year view, a radial spiral where each full turn = one year and shipped projects sit as beads along the spiral, color = kind (theme build / app module / migration). Strong "florituras" motion candidate: the spiral can literally draw itself in on scroll (`stroke-dashoffset` sweep synced to Lenis scroll progress).
18. **Polar/radial clock motif for the "Now" pill** — a tiny radial ticker (like Observable's Polar Clock) sitting inside or beside the existing Now pill, giving a literal "live" sense (current local time in Bogotá/wherever, or days since last shipped project) without inventing a fake metric — every value must be real and derivable (Date math), not decorative-only.
19. **On-brand 404/empty-state copy (Pudding pattern)** — "THIS SITE REQUIRES FLASH... Just kidding" is a good model for Maxfolio's own 404 or empty-filter states in the Shopify Work index: a joke setup + honest correction + a way back. Ties to the existing memory rule that filters must show a real "0 results" canary, never fabricate.
20. **Editorial magazine grid with hand-drawn byline glyphs (Nightingale pattern)** — for a blog/notes section if one is ever added: dark hero band, small illustrated "byline" icon per post instead of an avatar photo, slide-dot pagination under the hero.
21. **Nebula/gradient CSS backdrop behind a headline stat (Octoverse)** — reusable ambient background technique: 2-3 soft radial-gradient blobs + a subtle noise texture (SVG `feTurbulence`, or a tiled 64×64 noise PNG) sitting behind any single big-stat moment. Pure CSS + one small SVG filter, no canvas/WebGL, cheap on mobile.
22. **"Fix my chart" pairing as a CRO/before-after case-study module** — reuse idea #7's diagonal-split mechanic specifically for the Shopify Work case-study sheet's "before Digitdeck" vs "after Digitdeck" storefront screenshots, since that pairing already exists conceptually in the case-study charts section — this gives it a sharper, more editorial frame than a plain side-by-side.

## 3. Avoid list

- **Dual-axis charts** (Datawrapper's own explainer): two different y-scales on one chart reliably misleads readers about correlation — never use for e.g. "stores shipped" vs "years" on the same axis pair.
- **Client-heavy chart bundles that never paint** — Information Is Beautiful's showcase and Flourish's examples page both shipped multi-second JS bundles that either blanked or timed out in a plain headless run; anything built for Maxfolio must render its critical chart content server-side/statically, JS only for interaction layered on top (matches the existing performance-by-construction doctrine).
- **Decorative-only "live" numbers** — a radial clock or ticker that looks live but is actually static is a classic dataviz anti-pattern (WTF Visualizations' whole premise, even though the site itself was unreachable this pass); every "live" element here must compute from a real value (Date.now(), real counts) or not claim liveness at all.
- **Legend-only color coding** — several Observable notebooks and the OECD flower chart lean on color+legend alone; for mobile-first accessibility, label critical series directly on the mark, don't force a legend lookup.
- **CAPTCHA/bot-walled "inspiration" sources** — Bloomberg Graphics and NYT Upshot were both behind bot-detection during this pass; don't build scrapers or automation that tries to defeat them — treat as inaccessible and move to an alternate source (as this run did).
- **Fabricated/round-number "stats"** — Spotify Wrapped's whole genre depends on precise personalized numbers; Maxfolio's absolute-honesty rule means any similar "your year in review"-style module must pull from real git/registry data or must not ship.
