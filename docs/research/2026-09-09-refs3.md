## 2. Idea catalog (28 ideas)

### Hero / index reimagining

**1. Fading project-list hero over generative illustration**
Look: name + role centered top; a full-bleed, softly-lit generative/illustrated background (wave-line figure); below it, a vertical stack of project titles in serif italic, each successive line a step darker/lower-opacity, forming a natural depth fade. No cards, no borders — text is the only UI.
Section: Projects index or Shopify Work index, as an alternate "quiet" opener.
Sketch: absolutely-positioned `<ul>` over a CSS/SVG gradient-mesh or `<canvas>` background; each `<li>` gets `opacity: calc(1 - var(--i) * 0.08)`; stagger fade-up on mount via framer-motion.
Perf/a11y: illustration must be a static SVG/gradient (no video) to keep LCP light; list items are real links, list semantics preserved for screen readers even though visually a decorative fade.
Screenshot: `targets/honestfi-full.png`, `targets/honestfi-mobile.png` (confirms clean mobile reflow — full list stays legible, no truncation).

**2. Two-tone lead paragraph + floating pill nav**
Look: hero paragraph splits into a bold black lead sentence and a lighter gray follow-on sentence in the same paragraph block (not a separate subhead); a pill-shaped nav capsule floats top-center, detached from the page edges.
Section: Hero (extends the already-planned inline-prose hero).
Sketch: `<p><strong>Lead sentence.</strong> <span class="text-muted">Follow-on sentence.</span></p>`; nav as `position:fixed; top:24px; left:50%; translateX(-50%)` pill, `backdrop-filter: blur()` for legibility over imagery.
Perf/a11y: ensure the muted-gray follow-on text still meets 4.5:1 contrast against the hero background — test both light/dark themes.
Screenshot: `targets/philipreadman-full.png`.

**3. Edge-bleeding offset project tile grid**

### New theme: Neumorphism / soft UI

**24. Neumorphism dual-shadow recipe (concrete, generator-verified)**
Look/values: light gray surface (`#e0e0e0`-class background), large border-radius (40-50px on primary cards), extruded "raised" look from two offset box-shadows sharing the surface hue — one lighter (highlight, upper-left), one darker (shadow, lower-right) — `box-shadow: 20px 20px 60px #bebebe, -20px -20px 60px #ffffff;` at default generator settings; a "pressed/inset" state swaps to `inset` shadows for active/selected controls.
Section: The new neumorphism theme's entire card/button/input system — this is the literal token contract.
Sketch: two custom properties, `--shadow-dark` and `--shadow-light`, both derived from the same base surface color (never pure black/white, always tinted from the surface hue) so it reads as one material; buttons toggle a `.pressed` class swapping to `inset` values.
Perf/a11y: **critical** — never animate `box-shadow` directly on interaction (expensive, causes paint on every frame and hurts INP per freefrontend.com's own guidance); instead crossfade opacity between a pre-rendered "raised" pseudo-element and a "pressed" pseudo-element, or use a single `filter: drop-shadow()` layer which composites more cheaply. Neumorphism is a known WCAG contrast risk — monochromatic shadow-only affordances fail for low-vision users, so every interactive neumorphic element needs a second, non-shadow signal (a border-color shift, an icon change, or a text-weight change) plus a visible `:focus-visible` ring that does NOT rely on the shadow pair.
Screenshot: `targets/neumorphismio-full.png`, `targets/freefrontend-neu-full.png`, `targets/freefrontend-neu-scroll35.png`.

## 3. Avoid list

- **Preloaders with no progress signal.** boc.studio's WebGL loader never resolved past its centered wordmark in either capture window (full load and mid-scroll) — a loader with no percentage, skeleton, or timeout reads as broken. Any loader maxfolio ships needs a visible progress cue and a hard timeout that shows real content regardless.
- **Autoplaying full-bleed video with no visible pause control.** kaiblamey.com's reel plays automatically behind the project index; always ship a pause affordance and a `prefers-reduced-motion` static fallback — award-gallery critique consistently flags autoplay video as an accessibility miss.
- **Randomized "scattered" layouts that read as generated, not art-directed.** The freeform card-scatter hero (okaydev.co) and letter-scatter reveal (jacobince.com) only work when every position/rotation is a deliberate, fixed value — the moment placement looks procedurally randomized per page-load it reads as AI-slop, which directly conflicts with the owner's explicit "zero AI-slop" rule. Always hand-place scatter values; never `Math.random()` them at runtime.
- **Neumorphism's known accessibility failure mode.** freefrontend.com and multiple award-gallery critiques note neumorphism's monochromatic shadow-only affordances fail WCAG contrast for low-vision users. Never ship a neumorphic control whose only state signal is a shadow change — pair with a color/border/icon shift and a real focus ring.
- **Animating `box-shadow` directly.** Confirmed by freefrontend.com's own performance note: box-shadow transitions are compositor-unfriendly and hurt INP. This applies doubly to a whole page of neumorphic buttons/cards — build the pressed/raised states as crossfaded layers, not animated shadow values.
- **Cookie-consent banners eating the hero.** readymag.website's consent banner overlapped the bio copy on load — if any third-party embed needs consent, position it so it never obstructs the primary CTA, especially on mobile viewports.
- **Reproducing copyrighted Persona/Atlus assets, fonts, or exact iconography.** Every idea in section §25-28 is written as reusable geometry/color/type technique, deliberately not tied to Atlus's specific typefaces, character art, or UI copy — the new theme must evoke the mood through original shapes and maxfolio's own palette, never trace or crop actual game screenshots.
- **Halftone/comic treatments used everywhere.** The dedicated "halftone comic panel" search turned up almost no web-portfolio precedent — it is a print/stock-photo technique, not a common web one. Use it sparingly (one hero texture, one project-tile treatment) as a differentiator rather than a page-wide motif, or it will fight the "editorial, not gimmicky" brief.
