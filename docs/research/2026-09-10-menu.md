# maxfolio.dev — Build Menu (synthesis of wf5 lenses)

Synthesized from: `wf5-awwwards-portfolio-a.md` [A], `wf5-awwwards-portfolio-b.md` [B],
`wf5-dribbble-portfolio.md` [Dr], `wf5-three-d-scroll.md` [3D], `wf5-data-rich-portfolios.md` [DR],
`wf5-sections-and-transitions.md` [ST]. Screenshot paths below are relative to
`…/scratchpad/refs4/`. Themes referenced: Apple Clean (default), Luxury, Brutalist, Soft UI,
Arcade, Menu, + the three NEW proposals in Part B.

Hard constraints threaded through every item (do not relitigate per-item): **real numbers only**
(never fabricate a stat, counter, badge, or rating); **mobile-first**; **one `WebGLRenderer` per
page**; every animated/scroll-jacked pattern needs a keyboard + `prefers-reduced-motion` fallback
that is not simply "hidden"; every data-as-visual needs a genuine HTML/text equivalent.

## PART A — 50-item build menu

### 1. Hero & structure (8)

#### H1. Numbered-glyph nav instead of a menu bar
**What:** primary nav rendered as `01 Work / 02 About / 03 Playground / 04 Contact` at headline weight, not tucked into a hamburger/small top-right menu.
**Ref:** [A] `awwwards-portfolio-a/studio-merge/vp-0.png`, `see-me` text.
**Themes:** Apple Clean, Brutalist, new Terminal.
**Effort:** S. **Lighthouse risk:** none (static markup). **A11y:** real `<a href="#...">`, not `<button onClick>`, so it's a working same-page nav for keyboard/SR users.
**Sketch:**
- Flex row of `<a>` with a `<span class="tabular-nums">01</span>` prefix.
- Two nested spans per link so number/label can animate color/weight independently on hover.
- No JS required beyond a CSS `:hover` rule.

#### H2. Oversized flat brand-mark as hero centerpiece
**What:** instead of a photo/illustration, the hero's visual anchor is the wordmark/mark itself, huge and flat, copy arranged asymmetrically around it.
**Ref:** [ST] `sections-and-transitions/vercel/vp-0.png`.
**Themes:** Apple Clean (alt hero), Brutalist.
**Effort:** S. **Lighthouse risk:** none (inline SVG). **A11y:** mark `aria-hidden="true"` on the decorative SVG, keep a real `<h1>` text sibling.
**Sketch:**
- SVG mark scaled with `clamp()` viewport units.
- CSS grid: headline in one cell, mark spanning behind/through it via z-index under the baseline.
- No animation required; optional stagger fade-in on load.

#### H3. Full-bleed editorial hero with overlapping serif/sans type
**What:** a large photographic hero image bleeds edge-to-edge; a serif display line and a sans utility line stack and slightly overlap the image's foreground subject rather than sitting in a safe zone.
**Ref:** [ST] `sections-and-transitions/locomotive/vp-0.png`.
**Themes:** new Editorial theme, Luxury.
**Effort:** M. **Lighthouse risk:** Medium — one heavy hero image, must preload + `srcset`. **A11y:** real DOM text (not baked into image); verify contrast across the image's tonal range, add scrim fallback if a blend-mode ever fails contrast.
**Sketch:**
- Absolute-positioned text block, negative margin pulling it over the image's lower third.
- `mix-blend-mode: difference` (optional) or drop-shadow for legibility across varying tones.
- Responsive `<img>`/`<picture>` with explicit dimensions to avoid CLS.

#### H4. Duotone portrait hero with split outline/solid wordmark
**What:** large monochrome/duotone portrait under the fold; the name is set as one word stroke-only (outline) and one word solid, same baseline, read as one lockup.
**Ref:** [Dr] `dribbble-portfolio/001-26995447-personal-portfolio-website-animations/vp-0.png`.
**Themes:** new Editorial theme, Apple Clean.
**Effort:** M. **Lighthouse risk:** Low-Medium — one optimized portrait (AVIF/WebP, explicit dims). **A11y:** stroke-only text can fail contrast; add a solid-color fallback under `prefers-contrast: more`. Portrait must be the owner's real photo, license-clean.
**Sketch:**
- `text-transparent [-webkit-text-stroke:2px_var(--ink)]` for the outline word, solid sibling span.
- Portrait `<img>` with `grayscale contrast-110`.
- Framer-motion stagger fade/`y` on load only (above-the-fold, no scroll trigger needed).

#### H5. Theme picker as the primary hero interaction
**What:** instead of a settings menu, the hero itself invites the visitor to pick a working style/mood (Apple/Luxury/Brutalist/Arcade/…) as the very first interaction, and the section below crossfades/re-renders per selection.
**Ref:** [A] `awwwards-portfolio-a/allhaus/vp-0.png` (geographic-state picker pattern).
**Themes:** all — this is the "explore themes" front door.
**Effort:** M. **Lighthouse risk:** Low, if the swapped preview content is lazy-loaded per selection. **A11y:** real `<button role="radio">`/`<a>` elements with clear focus states, never click-only divs.
**Sketch:**
- Large toggle buttons in a row/grid, one per theme.
- Selecting one crossfades the section below via controlled state.
- Reuses maxfolio's existing theme-routing, just moved earlier in the funnel.

#### H6. Diagonal gradient-mesh ribbon hero background
**What:** a soft, grainy, multi-hue gradient shape (visible cloth-like folds, not a flat gradient) sweeps diagonally behind hero copy.
**Ref:** [ST] `sections-and-transitions/stripe/vp-0.png`.
**Themes:** Soft UI.
**Effort:** S. **Lighthouse risk:** Low — pure CSS, no image request. **A11y:** decorative, `aria-hidden`; check text contrast against the busiest part of the gradient.
**Sketch:**
- Layered `radial-gradient`/`conic-gradient`, blurred via `filter: blur()`.
- Slow `background-position`/`rotate()` loop, 8–15s ease-in-out infinite.
- Optional low-opacity SVG `feTurbulence` grain overlay for "fabric" texture.

#### H7. Sticky "chapters" side-progress nav for the whole single page
**What:** a slim fixed rail (dots/short labels) tracks which of maxfolio's ~13 sections the visitor is in, highlighting the active one with jump-to links.
**Ref:** [ST] `sections-and-transitions/awwwards-collections/vp-35.png` (named "Transitions"/nav-pattern collection).
**Themes:** all, desktop-only.
**Effort:** M. **Lighthouse risk:** Low — one shared `IntersectionObserver`. **A11y:** real anchor links, keyboard-focusable, `aria-current="location"` on the active dot; hide on mobile where vertical space is precious.
**Sketch:**
- One `IntersectionObserver` (threshold 0.5) watching all section roots, one shared `activeSection` state.
- Rail items are real `<a>` with `scroll-behavior: smooth`/`scrollIntoView`.
- Framer-motion animates the active dot's scale/color only.

#### H8. Word-for-word headline rotator with letter-mask wipe
**What:** a small qualifier phrase precedes a headline word that cycles through several nouns/roles ("Shopify Engineer" → "Systems Builder" → …), each swap via a vertical mask wipe, not a plain crossfade.
**Ref:** [ST] `sections-and-transitions/hello-monday/vp-0.png`; [B] `awwwards-portfolio-b/sly-clubop-site/text.txt` (wordmark→letter-break variant).
**Themes:** all typographic heroes.
**Effort:** S. **Lighthouse risk:** none. **A11y:** keep the full word list as static/visually-hidden text or `aria-live="off"`; pause rotation under `prefers-reduced-motion` (show one word).
**Sketch:**
- `AnimatePresence` around the swapped word inside an `overflow-hidden` wrapper sized to the widest word (fixed `min-width` measured via `useLayoutEffect`).
- `initial={{y:"100%"}}` / `exit={{y:"-100%"}}`.
- `setInterval` bump of index; pause on hover/focus.

### 2. Showing work / case studies (8)

#### W1. Split-screen serif index with full-row hover-swap media
**What:** each project row is set in large serif type; hovering swaps a fixed-position media panel to that row's image/video while the row underlines and scales slightly.
**Ref:** [ST] `sections-and-transitions/locomotive/vp-35.png`.
**Themes:** Apple Clean, new Editorial (storefront index / projects index).
**Effort:** M. **Lighthouse risk:** Low if only the hovered image decodes eagerly. **A11y:** each row is a real `<a>` with descriptive text; focus must trigger the same preview as hover (not hover-only).
**Sketch:**
- One `motion.div` preview panel, position synced to hovered row's `y`.
- `AnimatePresence mode="wait"` crossfades the image on row change.
- Lazy-decode images on first hover-of-index, not all at once.

#### W2. Indexed work list with cursor-following hover thumbnail
**What:** a numbered plain-text project list (01, 02, 03…) with hairline dividers; hovering a row floats a thumbnail near the cursor.
**Ref:** [Dr] `dribbble-portfolio/018-27550614-.../full.png` (own copy: "Indexed Work List").
**Themes:** Apple Clean, Brutalist.
**Effort:** M. **Lighthouse risk:** Low — thumbnails lazy-decoded on first hover. **A11y:** on focus/tap, show the thumbnail inline below the row (no touch equivalent to mouse-follow).
**Sketch:**
- `useMotionValue` for cursor x/y, absolutely-positioned `motion.div` thumbnail following with a spring (`stiffness:300, damping:30`).
- `AnimatePresence` fade on `onMouseEnter`/`onFocus`.
- Keyboard fallback renders the same thumbnail statically under the focused row.

#### W3. Case-row "spec sheet" index (index-as-metadata table)
**What:** each project row is captioned like a film credit: location/timezone, medium, duration, year, studio — replacing plain title+thumbnail with a denser "production credits" line.
**Ref:** [A] `awwwards-portfolio-a/untitled/vp-0.png`, `huy-phan-vol-2` text.
**Themes:** Apple Clean, new Editorial (storefront index / case-study sheet).
**Effort:** S. **Lighthouse risk:** none, static markup. **A11y:** the dense row must still read as one semantic `<li>`/link, not five fragments.
**Sketch:**
- CSS grid row template `[title][stack][role][launch][year]`.
- Data comes from existing case-study frontmatter, no new content model.
- No animation required beyond a hairline divider.

#### W4. Film-credit card template (Title/Role/Stack/Result)
**What:** every case study uses the exact same fixed four-row "credit block" — Client / Role / Stack / Result — for instant scannability regardless of project size.
**Ref:** [B] `awwwards-portfolio-b/iancoad-com/text.txt`.
**Themes:** all case-study sheets.
**Effort:** S. **Lighthouse risk:** none. **A11y:** real `<dl><dt>/<dd>` pairing.
**Sketch:**
- One `<CreditCard rows={[...]}/>` component reused everywhere.
- Rows fade in top-to-bottom with a short `whileInView` stagger.
- Data-driven from the same case-study source as W3.

#### W5. Center-scaled "focus" carousel
**What:** a horizontal project carousel where the centered card is visibly larger with a glow/border while neighbors are smaller, dimmed, and cropped at the edge.
**Ref:** [B] `awwwards-portfolio-b/ohhmydesign-com/full.png`.
**Themes:** gallery carousel upgrade, all themes.
**Effort:** M. **Lighthouse risk:** Low — transform-only. **A11y:** must stay drag/keyboard operable (arrow keys move focus); drop the scale delta under `prefers-reduced-motion`.
**Sketch:**
- `scale`/`opacity` interpolated from each card's distance-from-center via `useTransform` on a shared scroll/drag progress value.
- CSS `scroll-snap-type: x mandatory`.
- Arrow-key handler bound to the same progress value as drag.

#### W6. Full-bleed environmental photo + oversized serif case-study title
**What:** a warm lifestyle/product photo fills the case-study cover; a large serif headline sits over it like a film title card, not a UI screenshot.
**Ref:** [Dr] `dribbble-portfolio/048-27716792-cubee-solar-energy-app-redesign-brand-identity/vp-0.png`.
**Themes:** new Editorial, Luxury.
**Effort:** M. **Lighthouse risk:** Medium — one hero-weight image per case study, needs `srcset`/lazy for below-fold instances. **A11y:** Ken-Burns zoom must respect `prefers-reduced-motion`; real photos only (no stock imagery misrepresenting the work).
**Sketch:**
- `<img class="object-cover h-[70vh]">` + overlay `<h2 class="font-serif text-6xl md:text-8xl">`.
- `whileInView` opacity/y fade for the title.
- Optional slow `scale:[1,1.05]` Ken-Burns over 8s, static fallback under reduced-motion.

#### W7. Product macro-shot inside a real browser-chrome frame
**What:** the case-study preview sits inside a faithful browser window (traffic-light dots, address-bar text) around a soft-studio product photo — reads as "a real live site" rather than a flat screenshot.
**Ref:** [Dr] `dribbble-portfolio/063-25273962-industrial-designer-portfolio-website-for-mirko-romanelli/vp-0.png`.
**Themes:** all storefront-index thumbnails.
**Effort:** S. **Lighthouse risk:** Low, unless using a live `<iframe>` (lazy-load it, poster fallback until in view). **A11y:** fake URL text marked `aria-hidden` unless it's a real link.
**Sketch:**
- Reusable `<BrowserFrame url="…">` component: rounded top bar, three dot spans, URL pill.
- `<img>` (preferred) or lazy `<iframe>` below.
- Regenerate the screenshot whenever the real store/theme changes (flag as a content-maintenance task, see Avoid list).

#### W8. Grayscale-to-color hover/focus reveal for photo grids
**What:** thumbnails render desaturated by default, snap to full color on hover/focus, for an editorial gallery-like restraint.
**Ref:** [Dr] `dribbble-portfolio/056-6255556-getz-photography-portfolio-website/`.
**Themes:** gallery carousel, storefront index, new Editorial.
**Effort:** S. **Lighthouse risk:** none — filter transition only. **A11y:** trigger the same reveal via `:focus-visible` or "tap to preview" for touch devices with no hover.
**Sketch:**
- `filter: grayscale(1)` default, `transition: filter .4s ease`, `hover/focus:grayscale-0`.
- Transition only on `filter` (GPU-composited), never on layout properties.
- Touch fallback: tap toggles the class.

### 3. Data & timelines with real data (8)

#### D1. Sticky-rail resume timeline
**What:** pinned left column (name/nav/socials) while the right column scrolls through dated role blocks (`2024 — PRESENT`), nav dot filling in as the visitor scrolls past.
**Ref:** [DR] `data-rich-portfolios/brittany-chiang/vp-0.png`.
**Themes:** Apple Clean, Menu — new "Experience" section.
**Effort:** M. **Lighthouse risk:** Low — CSS sticky + one `IntersectionObserver`. **A11y:** nav is real links (`href="#role-id"`); underline animation respects `prefers-reduced-motion`.
**Sketch:**
- CSS `position: sticky` left column, `IntersectionObserver` per role block toggling active nav state.
- Framer-motion `layoutId` moving underline between active years.
- No scroll-jacking — pure class-swap.

#### D2. Role key/value spec table (Position/Location/Industry/Website)
**What:** each job entry rendered as a small honest table instead of a prose paragraph.
**Ref:** [DR] `data-rich-portfolios/awwwards-experience-andrey-mitko/vp-0.png`.
**Themes:** Apple Clean, Soft UI.
**Effort:** S. **Lighthouse risk:** none. **A11y:** real `<dl>/<dt>/<dd>`, not `<div>` soup.
**Sketch:**
- CSS grid `grid-template-columns: max-content 1fr` per row.
- Company name as `<h3>` above the table.
- Static content, no animation required.

#### D3. GitHub-Skyline-style 3D year skyline
**What:** a year's real contribution/deploy data turned into an orbitable 3D bar skyline replacing the flat years chart.
**Ref:** [DR] `data-rich-portfolios/github-skyline/vp-0.png`; [3D] catalog #16 (3D bar/column extrusion).
**Themes:** new Skyline theme (signature), Arcade, Brutalist.
**Effort:** L. **Lighthouse risk:** High if mishandled — must lazy-mount only in-viewport, on-demand render (no continuous RAF), `OrbitControls` locked to a narrow angle. **A11y:** `role="img"` + text summary of total contributions; static PNG poster for reduced-motion/low-power; a genuine `<table>`/list of the same values must exist in the DOM.
**Sketch:**
- `THREE.InstancedMesh` of boxes, height = real weekly/daily activity count (build-time GitHub GraphQL fetch, cached to JSON).
- Scroll rotates camera via `useScroll` (r3f/drei), on-demand `invalidateFrameloop`.
- Static poster fallback + real `<table>` sibling.

#### D4. Composited multi-chart "dashboard" hero visual
**What:** one tilted glass panel layering a line chart, bar chart, donut, and radial gauge — built from maxfolio's own real numbers (years, stores shipped, uptime), not a mockup.
**Ref:** [DR] `data-rich-portfolios/wakatime/vp-0.png`.
**Themes:** Apple Clean stat band, new Skyline theme.
**Effort:** M. **Lighthouse risk:** Low if hand-rolled SVG (avoid a heavy charting library). **A11y:** each mini-chart needs a `<title>`/visually-hidden text summary since decorative-but-informative.
**Sketch:**
- Four small hand-rolled SVG widgets (`<path>`/`<rect>`) absolutely positioned inside one rounded card.
- `transform: perspective() rotateY()` tilt.
- `whileInView` stagger-fade per mini-chart; real data only.

#### D5. Overlapping-roles Gantt-style bar chart
**What:** horizontal bars per employer/engagement allowed to overlap in time (freelance + contract concurrently), with a "today" marker — reads instantly and is 100% real.
**Ref:** [DR] catalog #12 (no dedicated screenshot; pattern description).
**Themes:** replaces/augments the years chart, all themes.
**Effort:** M. **Lighthouse risk:** none — SVG with <20 bars is free. **A11y:** each bar focusable (`tabindex=0`) with `aria-label="Digitdeck, 2023–present"`.
**Sketch:**
- Hand-rolled SVG, bar `x`/`width` from real date ranges via a simple linear timeScale.
- Hover/tap tooltip shows role + dates.
- "Today" vertical marker line.

#### D6. Delivery-window calendar heatmap (GitHub-contribution style)
**What:** a weeks×days grid colored by intensity, scoped to real ship/deploy dates (theme pushes, launches) rather than fabricated activity.
**Ref:** [DR] catalog #15.
**Themes:** stat band companion, all themes.
**Effort:** M. **Lighthouse risk:** Low — a ~365×N div grid is cheap; virtualize only if multiple years shown at once. **A11y:** each cell `title="12 Mar 2026 — 2 deploys"`, whole grid behind a text summary for SR users.
**Sketch:**
- CSS grid of small squares, color via a CSS custom property driven by `data-count`.
- Data generated from real git log/Shopify CLI deploy history at build time.
- Never fabricated — build script fails loudly if source data is missing.

#### D7. "Years of work" honest counter (no exaggeration)
**What:** a single stat like "9 years shipping Shopify" computed at build time from a real start date, never hardcoded so it can't go stale or lie.
**Ref:** [DR] catalog #11.
**Themes:** stat band, all themes.
**Effort:** S. **Lighthouse risk:** none. **A11y:** final value present in DOM text (not canvas-only); skip the count-up animation under `prefers-reduced-motion` and show the final number immediately.
**Sketch:**
- Tiny build-time script writes `years-of-work.json` from `new Date() - START_DATE`.
- Component reads it, animates count-up via `useMotionValue`+`useTransform` on `whileInView`.
- Static number always present as the accessible fallback.

#### D8. Live one-line real stat as a trust signal
**What:** a single small line above/near the hero headline states a real, continuously-incrementing number (fetched server-side, animated client-side) — reads as "genuinely live," not decorative.
**Ref:** [ST] `sections-and-transitions/stripe/vp-0.png` ("Global GDP running on Stripe: 1.71…%" — mechanism only, never the value).
**Themes:** stat band, all themes.
**Effort:** M. **Lighthouse risk:** none — tiny DOM text node. **A11y:** `aria-live="off"` after settling (a fast-ticking live region is disorienting for SR users); expose the final static value as the accessible name.
**Sketch:**
- Fetch the real figure server-side (GitHub/npm API) at build time — never invent it client-side.
- Animate count-up via `requestAnimationFrame` easing over ~1.2s on mount.
- Cache aggressively; never poll the third-party API on every page view.

### 5. Imagery + 3D on scroll (8)

#### I1. Scroll-scrubbed single hero object (rotate + zoom tied to scrollY)
**What:** one 3D object (monogram, abstract shape) rotates and dollies toward camera as the hero section scrolls, no easing lag once the wheel releases.
**Ref:** [3D] catalog #1; `three-d-scroll/lusion-co/vp-0.png`, `three-d-scroll/spline-design-community/vp-0.png`.
**Themes:** Apple Clean (glass/metal monogram), Luxury (gold ring/abstract form), new Skyline.
**Effort:** L. **Lighthouse risk:** High if not gated — desktop-only load (`matchMedia`), lazy-mount, cap DPR at 1.5, pause RAF via `IntersectionObserver` off-screen. **A11y:** `prefers-reduced-motion` freezes at a static rotation; canvas `aria-hidden`, real heading/CTA remain as normal HTML around it.
**Sketch:**
- Read `scrollYProgress` (window scroll / section height); write to `mesh.rotation.y`/`camera.position.z` inside `requestAnimationFrame`, never inside the scroll handler.
- Desktop-only (`(min-width:1024px) and (pointer:fine)`).
- Static PNG fallback for mobile/low-end/reduced-motion.

#### I2. Sticky "product scrub" pinned section
**What:** a section becomes `position: sticky` for N viewport-heights while a 3D object completes a multi-stage transform (assemble → explode → reassemble) as the visitor scrolls.
**Ref:** [3D] catalog #2.
**Themes:** process stepper reimagined, years-chart reimagined.
**Effort:** L. **Lighthouse risk:** Medium-High — only start the WebGL context when the sticky wrapper enters viewport; dispose geometries/renderer on unmount (SPA route change) to avoid GPU memory leaks. **A11y:** reduced-motion renders only the final-state frame as a static image; verify momentum-scroll doesn't create a jank trap.
**Sketch:**
- CSS `position: sticky; height:100vh` inside a tall (`300vh`) scroll track.
- `useScroll({target: trackRef})` → `scrollYProgress` drives both the 3D camera/mesh AND DOM captions via `useTransform`.
- Destroy renderer on unmount.

#### I3. Procedural no-external-model geometry, themed per experience
**What:** torus-knot / faceted icosahedron crystal cluster / MarchingCubes metaball field — all zero-asset, procedurally generated 3D signature shapes, no GLTF licensing risk.
**Ref:** [3D] catalog #6–8; `three-d-scroll/spline-design-community/vp-0.png`.
**Themes:** Apple Clean (torus-knot + matcap), Luxury (gold crystal cluster), Soft UI (metaball blobs), new Skyline.
**Effort:** M. **Lighthouse risk:** Low-Medium — single mesh (torus-knot/crystals) is cheap; metaballs cost scales with grid resolution (cap at 28–32³, skip on mobile). **A11y:** decorative, `aria-hidden`; static blurred-PNG fallback on mobile for metaballs.
**Sketch:**
- `TorusKnotGeometry`+`MeshMatcapMaterial` (procedural gradient matcap, ~20KB, no HDRI needed).
- `IcosahedronGeometry(r,0)` instances in a `Group`, gold `MeshPhysicalMaterial` for Luxury.
- `MarchingCubes` (three.js `examples/jsm`) at low res for Soft UI blobs.

#### I4. GPU-instanced particle field with scroll-linked spread
**What:** a sparse point cloud, tight/still at rest, expands/swirls outward as the visitor scrolls past a section — the cheapest genuine "live 3D" effect in the catalog.
**Ref:** [3D] catalog #9.
**Themes:** transition moments (hero→stat band), Arcade CTA impact bursts.
**Effort:** M. **Lighthouse risk:** Low — GPU-instanced, thousands of points cost almost nothing versus mesh geometry; good candidate to keep on for reduced-motion users if displacement is kept small.
**A11y:** purely ambient/decorative, `aria-hidden`.
**Sketch:**
- `THREE.Points` + `BufferGeometry`, positions randomized in a sphere.
- Scroll progress drives a `uSpread` uniform in a custom vertex shader displacing points outward.
- On-demand render, pause off-screen via `IntersectionObserver`.

#### I5. 3D bar/column extrusion for the years-chart, with mandatory HTML table
**What:** each year's bar is an extruded 3D column at a slight isometric angle; bars grow 0→real height staggered on scroll, camera does a slow settle-orbit.
**Ref:** [3D] catalog #16.

**Effort:** M. **Lighthouse risk:** Medium — cap bar count, HTML label overlays via `camera.project()` math (not baked into geometry). **A11y:** hard requirement — pair with a genuine `<table>` or visually-hidden list of the same values; heights map 1:1 to the real metric, no decorative scaling.
**Sketch:**
- `BoxGeometry` per data point, `scale.y` animated 0→value keyed to scroll-into-view (stagger index×80ms).
- Real HTML labels positioned via camera projection, not sprites.
- `<table>` sibling always present in the DOM.

#### I6. Loading-percentage gate before a heavy 3D hero reveals

**Sketch:**
- Track `THREE.LoadingManager.onProgress`, render % as a normal DOM overlay (CSS width transition, not canvas text).

#### I7. Blur-up progressive image loading everywhere
**What:** every project/case-study image fades in from a tiny blurred low-res placeholder to the sharp final image on scroll-into-view, instead of popping in or showing a blank box.

**Themes:** all image-heavy sections (gallery carousel, storefront index, case-study sheet).

#### I8. Dark 3D hero with tilted device frame over a textured environment

**Ref:** [Dr] `dribbble-portfolio/058-24974265-dc-futuristic-modern-minimal-metal-portfolio-website-about-us/vp-0.png`.

### 6. Transitions & effects (8)

#### T1. Faceted-mask loader-to-site reveal
**What:** the loader's shape is a low-poly diamond/facet pattern that fractures outward, glimpsing the already-rendered page through the gaps before the mask fully dissolves.
**Ref:** [ST] `sections-and-transitions/obys/vp-0.png`, `obys/vp-70.png`.
**Themes:** new Terminal/Arcade entry moment, or a one-off Easter egg on `/explore`.
**Effort:** M. **Lighthouse risk:** Low — SVG-driven masks are cheap; avoid a canvas re-render loop. **A11y:** reduced-motion + explicit skip affordance, same as any loader; hard timeout.
**Sketch:**

- Skip control + hard timeout per the Avoid list.

#### T2. Custom mask-reveal on scroll (clip-path wipe)
**What:** instead of fade/slide, an element becomes visible through an animated `clip-path` (growing circle, widening bar, diagonal wipe) synced to scroll or `whileInView`.
**Ref:** [ST] catalog #20.
**Themes:** manifesto band (line-by-line wipe), all themes.
**Effort:** S. **Lighthouse risk:** Low — `clip-path` is compositor-friendly. **A11y:** content must exist in the DOM (not `display:none`'d) so it's readable pre-animation for AT/print/reduced-motion users; reduced-motion shows it immediately at full clip.
**Sketch:**
- `motion.div` `clip-path: inset(0 100% 0 0)` → `inset(0 0 0 0)` on `whileInView`.
- Or circular `clip-path: circle(0% at 50% 50%)` → `circle(150%...)` for a spotlight reveal.
- Reduced-motion variant skips straight to the end state.

#### T3. Curtain/panel page transition between routes
**What:** navigating between theme experiences/project pages sweeps a solid-color panel in from one edge, covers the viewport, the new page mounts underneath, then sweeps out.
**Ref:** [ST] catalog #21; [ST] Avoid list — house-documented `AnimatePresence`/`Outlet` gotcha.
**Themes:** all — the shared route-change chrome.
**Effort:** M. **Lighthouse risk:** none. **A11y:** move focus to the new page's `<h1>` after the transition completes, never before; reduced-motion cuts it to an instant cross-fade.
**Sketch:**
- Top-level `AnimatePresence` wraps a sibling `motion.div` panel — **never** the router `<Outlet/>` itself with `exit`.
- Panel animates `scaleY`/`translateY` in on the old route, out on the new route once mounted.
- Transform-only, under ~500ms combined.

#### T4. Magnetic navigation / cursor-follow buttons
**What:** nav links/CTAs subtly pull toward the cursor within a small radius before click; a custom cursor morphs size over interactive elements. Desktop-only.
**Ref:** [ST] `sections-and-transitions/lusion/vp-0.png`, `dogstudio/vp-35.png`.
**Themes:** new Terminal (nav), contact CTA, skills chips (sparingly).
**Effort:** M. **Lighthouse risk:** Low — attach listener only while the pointer is within a bounding box, skip entirely on touch (`(hover:hover) and (pointer:fine)`). **A11y:** never move the focus outline with this effect; keep the actual hit-area unaffected/generous; disable under reduced-motion.
**Sketch:**
- On `mousemove`, compute distance from cursor to each magnetic element's center.
- Within threshold radius, apply `translate` proportional to `(cursor-center)*strength` via spring motion values.
- Snap to `0,0` on `mouseleave`.

#### T5. Horizontal rail with scroll-jacked translateX + velocity skew
**What:** vertical scroll translates into horizontal card movement, cards scaling as they near center, with a velocity-driven skew ("whip") on fast scrolls that decays at rest.
**Ref:** [ST] catalog #19; [A] `awwwards-portfolio-a/senawa/vp-0.png` (horizontal filmstrip).
**Themes:** gallery carousel upgrade, years-chart alternate layout.
**Effort:** L. **Lighthouse risk:** Medium — transform-only (GPU-compositable), cap card image sizes, `content-visibility:auto` on offscreen cards. **A11y:** must remain arrow-key/tab navigable independent of scroll-jacking; ship a native `overflow-x:auto` fallback for reduced-motion.
**Sketch:**
- Pin section (`position:sticky`, tall track), map vertical scroll progress to horizontal `translateX` via `useScroll`+`useTransform`.
- Add `skewX` from `useVelocity`, decaying to 0 at rest.
- Bind Left/Right keys to the same progress value.

#### T6. Tilted, overlapping marquee of poster-style case cards
**What:** a horizontal band of case-study cards, some rotated a few degrees off-axis and overlapping neighbors, scrolls continuously as a ticker rather than a static grid.
**Ref:** [A] `awwwards-portfolio-a/studio-merge/vp-0.png`.
**Themes:** gallery carousel upgrade, Brutalist, Luxury.
**Effort:** M. **Lighthouse risk:** Low — GPU-composited transforms only, duplicate node list for seamless looping (never reset scroll position). **A11y:** the underlying case list must still exist as a normal, tab-reachable grid for reduced-motion/keyboard users.
**Sketch:**
- Flex row, each card `rotate(var(--tilt))` (per-card CSS custom property).
- Infinite marquee via translateX keyframes, negative margins/z-index for overlap.
- Reduced-motion renders the same cards as a static grid.

#### T7. Kinetic marquee band with crossed diagonal tape strips
**What:** two overlapping ribbon strips at a slight angle, each scrolling text infinitely in opposite directions, forming an X — a richer version of a single-row marquee.
**Ref:** [Dr] `dribbble-portfolio/018-27550614-.../full.png` (own copy: "Crossing tape strips add motion and personality").
**Themes:** existing ticker section upgrade.
**Effort:** S. **Lighthouse risk:** none — pure CSS transform. **A11y:** pause on `prefers-reduced-motion` and `visibilitychange`; mark `aria-hidden` if decorative/redundant with content already in nav/footer.
**Sketch:**
- Two absolutely-stacked divs, `rotate(-3deg)`/`rotate(3deg)`.

#### T8. Scroll-velocity-reactive material (chromatic aberration on fast scroll)
**What:** a 3D object/shader subtly glitches or smears on fast scroll and settles when the visitor slows down — reinforces "this responds to you."
**Ref:** [3D] catalog #12.
**Themes:** Brutalist (glitch fits raw aesthetic), Arcade (game-feel juice).
**Effort:** M. **Lighthouse risk:** Low — shader-only cost, negligible if scoped to one hero moment. **A11y:** disable under `prefers-reduced-motion` (a glitch effect is itself a motion-sensitivity trigger).

## PART B — Three new-theme proposals

### Theme 1: "Terminal" (dev/OS-boot identity)

- **Name:** Terminal (working title; alt: "SSH", "Root").
- **Palette:** near-black (`#0a0d0a`) ground; phosphor-green (`#39ff88`) or amber (`#ffb000`) single accent (user-togglable green/amber, like a real terminal preference), off-white body text at reduced opacity for readability, one desaturated red for error/warn states only.
- **Type:** monospace throughout — display in a heavier monospace (JetBrains Mono/IBM Plex Mono Bold), body in the regular weight; `tabular-nums` everywhere numbers appear.
- **Motifs:** `SYS.NAME` / `SYS.AUTH` / `STATUS: 200` / `UPTIME: Nd` boot readout; bracket-checkbox nav (`[·] WORK`, `[ ] ABOUT`); blueprint/graph-paper dot-grid background; live cursor X/Y coordinate readout in a corner; ASCII-art rendered logo/portrait; a literal dated CHANGELOG section versioning the site itself (`v2.1.1`).
- **Motion:** typewriter-effect line reveals on first load only (`sessionStorage`-gated, skippable, full text always present in the DOM — never built up via re-typed innerHTML); blinking `::after` cursor; faceted-mask boot-to-site reveal (T1) as the entry transition; magnetic cursor-follow on nav links (T4).
- **Imagery:** none, by design — the entire identity is typographic/ASCII. Any "photo" moment (About page) is rendered as ASCII-art (idea A#6) rather than a real photo, keeping the theme's visual grammar consistent.
- **Section-by-section:**
  - Hero: boot sequence → resolves to `SYS.NAME: Max Bustamante` / `SYS.ROLE: Shopify Tech Lead` typed line by line, ASCII logo, bracket nav.
  - Stat band: "data terminal" readout (DataRich#23) — `YEARS_ACTIVE: 9`, `STORES_LIVE: 6`, each line typed once.
  - Ticker: scrolls as a raw `tail -f`-style log line.

- **What makes it different from the existing six:** it is the only theme with zero photography and zero color beyond one phosphor accent — the most technical, engineer-for-engineers register in the set. Distinct from Brutalist (raw/grid-breaking but still full-color/full-type-scale) and from Arcade (playful game-menu, comic art, multi-color) by committing entirely to a monochrome command-line metaphor.

Every image must be the owner's own photography (per the copyright/authenticity Avoid rules) — this theme is the wrong choice if no real photo library exists yet.
- **Section-by-section:**
  - Hero: H4 duotone portrait + split outline/solid wordmark, kicker line above.

## PART C — Avoid list (consolidated across all six lenses)

1. **Never fabricate a stat, counter, badge, rating, or "live" number.** Every idea above that shows a number (D1–D8, F5, S3–S5, I5, I6, T8's "responds to you" framing) must map 1:1 to a real, sourced, currently-true value, with a real `<table>`/text equivalent alongside any chart or 3D visualization. This is the single rule that overrides every other tradeoff in this menu — house rule against invented ratings/placeholders applies with full force to a personal portfolio.
2. **Empty scroll-reveal sections captured mid-transition.** Never let a section be visually empty before its trigger fires — reserve space with a low-opacity placeholder or widen the `IntersectionObserver` `rootMargin` so first paint never shows dead whitespace. [A]
3. **Loaders/preloaders with no hard timeout.** Every gated reveal (T1, I6, H5's theme-swap) needs a hard timeout (3–4s) that force-reveals the page regardless of asset state — headless capture caught three studio sites (Resn, Active Theory, Lusion) stuck mid-animation, a real failure mode on slow connections/ad-blockers/restricted GPUs. [ST]
4. **`AnimatePresence exit` wrapping the router `<Outlet/>` itself.** House memory already documents this exact trap (leaves the new page at `opacity:0` on every navigation). Any curtain/panel transition (T3) must animate a sibling overlay, never the outlet's own exit.
5. **Scroll-jacking with no keyboard/reduced-motion escape hatch.** T5, I1, I2, D3 and any pinned/hijacked section must ship a native-scroll and keyboard-operable fallback alongside the enhanced version — the single most common accessibility complaint about this entire genre.
6. **More than one live `WebGLRenderer` context per page.** Kills mobile Safari especially (silently drops contexts past ~8–16 concurrent). Dispose geometries/materials/renderer on route change or GPU memory leaks across SPA navigation (documented production issue in the R3F/three.js community).
7. **Coupling 3D transforms directly inside the native `scroll` event handler.** Always read scroll value in the handler/`IntersectionObserver`, write to Three.js objects inside `requestAnimationFrame`.
8. **Baking informational text into canvas/WebGL.** 3D `TextGeometry` for real headings/stats/nav breaks SEO, screen readers, and text-selection — reserve 3D text for pure decoration with a real HTML duplicate.
9. **Heavy postprocessing (bloom/DoF/SSAO) on more than one section.** Pick a single hero moment; stacking full-screen passes across several sections is the fastest way to tank LCP/INP.
10. **Autoplaying a 3D loop or video/audio off-screen or without consent.** Always pause the RAF loop via `IntersectionObserver`; never default sound to on; ship muted-by-default video with a visible opt-in toggle (to-portfolio.com's pattern is correct, autoplay is not).
11. **Skipping the `prefers-reduced-motion` + mobile static-poster fallback on any 3D section.** Mandatory, not optional, across I1–I8, D3, D4.
12. **Duplicated nav items from an SSR/CSR hydration seam.** Diff `innerText` output for suspicious exact duplicates before shipping — cheap, high-signal QA (caught live on grigoletti.ch). [A]
13. **Ticking live clocks announced to assistive tech.** F4/B#16/B#19's live-clock pattern needs `aria-live="off"` explicitly — a per-second live region is one of the most disruptive SR experiences possible.
14. **Fake device/browser-chrome frames (W7) that never get regenerated.** They go stale the moment the real site changes underneath — only worth building with a process to refresh the embedded screenshot whenever the real UI ships.
15. **Cursor-following-only previews (W2) with no touch/keyboard equivalent.** Always ship a tap/focus fallback.
16. **Page-turn/book-flip navigation (Dribbble#25) as the sole way to browse.** Fine as an Arcade-theme bonus view, never the only way to reach the projects index — notoriously weak industry-wide for keyboard/SR support.
17. **Domain-guessing or presenting an unverified reference as confirmed.** [ST]'s "uns.gr" mistake — never fold an unverified guess into a shipped catalog entry.
18. **Stock photography or AI-generated "people" standing in for the owner.** H3, H4, W6, Editorial theme's whole identity depend on this being real, owned photography — never a stock developer.
19. **Stacking multiple independently-blurred glow layers.** Consolidate into one pre-blurred asset; compounds GPU cost badly on low-end devices.
20. **Auto-advancing carousels/crossfades with no pause control.** WCAG 2.2.2 requires pause/stop for anything moving automatically >5s (manifesto photo crossfades, DataRich#8 chapter photography, etc.).

## PART D — Gaps (not covered by any lens, worth a follow-up pass)

- **Mobile-native interaction patterns.** All six lenses skew desktop-hover-driven (magnetic cursors, cursor-follow thumbnails, mouse-parallax tilt). None dug specifically into touch-native equivalents beyond "add a tap fallback" — a dedicated mobile-interaction research pass (swipe gestures, bottom-sheet patterns, thumb-zone CTA placement) would sharpen the mobile-first mandate beyond fallback-only thinking.
- **Sound design governance.** Several references (Now Playing bar, ambient soundtrack toggles, terminal boot beeps) touch audio, but no lens addressed a house policy for when/whether maxfolio should have any sound at all, volume defaults, or how it interacts with a visitor's own media (tab audio, video calls). Worth a short explicit decision before building any of B#8/A#7.
- **Content pipeline / CMS for case studies.** W1–W8 all assume "existing case-study frontmatter," but no lens investigated how new case studies actually get authored/reviewed/published over time (MDX? a headless CMS? a JSON file in the repo?) — this affects how much of the fancy layout tooling (W1's hover-swap, W4's fixed credit rows) is sustainable to keep populated.
- **Real-data sourcing plan, concretely.** Many ideas (D1–D8, S3–S5, I5) say "pull from real GitHub/repo/deploy data" but no lens specified the actual pipeline: which API, what auth, how often it's refreshed, where the generated JSON lives, and what happens if the source is temporarily unavailable at build time. This is the single biggest execution risk in the whole menu given the hard "real numbers only" constraint.
- **Animation-library consistency.** The catalog freely mixes framer-motion, raw CSS `@keyframes`, GSAP-adjacent scroll-timeline mentions, and vanilla Three.js `useFrame` — no lens made a case for one canonical stack vs. situational use, which matters for bundle size and maintainability across nine themes.
- **Testing/perf-budget tooling for the new 3D work.** [3D] gives budgets (≤300KB gzipped per 3D section, cap DPR, etc.) but no lens covered how those budgets get enforced in CI (bundle-size checks, a Lighthouse-CI gate, a frame-time regression test) — worth wiring into the existing house Lighthouse/perf conventions before I1–I8 ship.
- **SEO/structured data for case studies.** None of the six lenses touched `JSON-LD`/`Article` schema, canonical URLs per case study, or OG-image generation for the richer case-study sheet (W1–W8) — worth a dedicated SEO pass once the new case-study template solidifies.
- **data-dd-* instrumentation for every new section.** Per the house `digitdeck-tracking` convention, every new component/section needs tracking hooks as a default, not an opt-in — none of the wf5 lenses considered this since they're pure design references; the eventual build pass must thread `data-dd-*` through all 50 items, especially the new interactive ones (H5 theme picker, S5 donut isolate, T3 route transitions).
- **Print/PDF export of a "resume" surface.** D1/D2/D5 all effectively rebuild resume-shaped data on the web; no lens considered whether a recruiter-facing printable/PDF resume export is worth offering alongside the visual timeline.
- **Governance for Easter eggs/scope creep.** Several ideas (H5's playful theme-picker framing, I8's device mockup, T1's faceted reveal, the "book" page-turn) are explicitly flagged as bonus/Easter-egg-only in their own sections — no lens proposed a rule for how many of these ship at once so the site doesn't become an unmaintainable pile of one-off flourishes; worth capping "signature moments" per theme (2–3, per the DataRich Avoid list's own restraint note) as an explicit build-planning constraint.
- **Cross-theme asset budget accounting.** With three new themes proposed (9 total) each carrying its own hero treatment (some 3D, some photography-heavy), no lens totaled the aggregate bundle/asset weight if a visitor tours all nine via the theme picker (H5) in one session — worth modeling total transferred bytes across a full "explore all themes" session, not just per-theme budgets.
