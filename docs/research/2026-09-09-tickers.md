# Lens: Tickers/Marquees — research digest (maxfolio)

Scope: horizontal/vertical scrolling text-and-media "marquee/ticker" mechanics — hover behaviors, direction/speed changes, curvature, 3D, velocity-reactivity, drag-scrub, and text-fill effects — evaluated for maxfolio's Now-pill ticker, stat band, Shopify-work index, gallery, skills ledger, manifesto band, and the two new themes (neumorphism, Persona-3 game-UI).

Baseline already in the codebase (for contrast, not to repeat): `src/components/common/Marquee.tsx` + `src/styles/index.css` — two counter-scrolling rows, CSS `@keyframes` on `transform: translateX(-50%)` only, duplicated track for a seamless loop, `mask-image` edge fade, `animation-play-state: paused` on `:hover`/`:focus-within`, and `@media (prefers-reduced-motion: reduce)` fully disables it. Every idea below is written as a delta or an alternative to this baseline, not a rebuild of it.

## 2. Ticker/marquee variant catalog (22 ideas)

### 1. Speed-up-on-hover (instead of pause)
- **Look:** Same two-row layout as the current `Marquee.tsx`. On hover/focus-within, `animation-duration` drops from 48s/56s to ~14s/16s (≈3.3× faster) over a 300ms ease-out transition, rather than freezing.
- **Section:** Now-pill ticker — signals "there's more, keep looking" instead of inviting a full stop.
- **Sketch:** CSS custom property `--marquee-dur` set on `.marquee-row`; `:hover`/`:focus-within` swaps it via a second custom property read by the same `@keyframes marquee` rule (`animation-duration: var(--marquee-dur)`). No JS.
- **Perf/a11y:** Transform-only, GPU-cheap. Must still fully stop under `prefers-reduced-motion`. Speeding up on hover reads worse for low-vision users than the current pause — keep pause-on-hover as the reduced-motion fallback and gate the speed-up variant behind `@media (prefers-reduced-motion: no-preference)`.
- **Shot:** n/a (CSS-only mechanic, not directly screenshotted).

### 2. Reverse-direction-on-hover
- **Look:** Row scrolls left→right normally; on hover it visibly decelerates, stops, and reverses to right→left for as long as the pointer stays, then resumes forward on mouseleave.
- **Section:** Shopify-work index ticker (store name strip) — hovering "rewinds" as a wayfinding cue before a click.
- **Sketch:** Swap `animation-direction: reverse` via a hover class; because the keyframe only translates `-50%`, reversing mid-cycle is visually seamless (no jump) since the loop is symmetric.
- **Perf/a11y:** Still transform-only. Needs `:focus-within` parity for keyboard users, and must not trigger on touch (no hover state) — verify with a `@media (hover: hover)` guard so touch users get tap-to-pause instead.
- **Shot:** n/a.

### 3. Pause-then-skew release (SVG offset-path variant)
- **Look:** Marquee follows a gentle wavy/curved SVG path instead of a straight line (Codrops/Daniel Petho technique) — text undulates as it scrolls.
- **Section:** Hero sub-line or a one-off accent under the typographic hero, used sparingly (not for the always-on Now ticker).
- **Sketch:** React + Motion (`framer-motion`, already a dependency): each duplicated text span gets `motion.div` with `style={{ offsetPath: 'path("M0,40 Q200,0 400,40 T800,40")', offsetDistance: '<animated %>' }}`, animated via a `useAnimationFrame` loop incrementing `offsetDistance`.
- **Perf/a11y:** `offset-path`/`offset-distance` animate as compositor-friendly properties in modern Chromium/Firefox but need a straight-line fallback for Safari <16 — feature-detect with `CSS.supports('offset-path', 'path("M0 0")')`. Reduced-motion: freeze at `offsetDistance: 0%`.
- **Shot:** `ddg-codrops-marquee-tutorial-full.png` (SERP evidence of the source tutorial).

### 4. Glowing SVG clip-path marquee
- **Look:** Marquee text rendered twice — a dim base layer and a bright, blurred "glow" layer clipped to the same text shape — scrolling together so the text appears to glow like a neon sign as it passes.
- **Section:** Manifesto inverted band (dark background) — this is exactly the kind of "one dramatic moment" a manifesto section wants.
- **Sketch:** SVG `<text>` twice in the same `<clipPath>`; the glow copy gets `filter: blur(6px)` + higher `fill-opacity`, both wrapped in one `<g>` that gets the existing `translateX` keyframe applied via CSS (SVG elements accept CSS transforms).
- **Perf/a11y:** `filter: blur()` is GPU-composited but costs more than plain transforms — keep the glow layer to a single small `<g>`, not the whole viewport; disable the blur layer entirely (keep only base text) under reduced-motion AND under a manual "reduce effects" toggle if one exists.
- **Shot:** `ddg-codrops-marquee-tutorial-full.png`.

### 5. Outline→filled text swap on hover
- **Look:** Ticker words render with `-webkit-text-stroke` (outline only, transparent fill) at rest; on hover, each word's fill wipes in from left to right (like a progress fill) in the accent color over ~250ms.
- **Section:** Skills usage ledger — turns a static tech-name list into a satisfying "light up what you touch" hover moment.
- **Sketch:** Two stacked absolutely-positioned copies of the same text: back copy has stroke only; front copy has solid fill and `clip-path: inset(0 100% 0 0)` at rest, animating to `inset(0 0 0 0)` on hover (`transition: clip-path 250ms var(--ease-standard)`).
- **Perf/a11y:** `clip-path` transitions are compositor-accelerated. Provide `:focus-visible` parity; the stroke-only resting state must still meet contrast/legibility (test at the design-system's minimum text size — thin strokes at small sizes can disappear on some renderers).
- **Shot:** `ddg-outline-fill-text-hover-full.png`.

### 6. Logo/image-strip marquee (grayscale→color on hover)
- **Look:** Row of small store/brand marks (not text) scrolling continuously at rest in grayscale/low-opacity; the one under the cursor snaps to full color + slight scale-up (1.08×) while the rest keep scrolling past it.
- **Section:** Shopify-work index — a compact "who we've built for" strip above or below the full case-study list.
- **Sketch:** React Bits' `Logo Loop` component is the direct reference (nav-confirmed, prop set not captured — treat as inspiration, not a copy target); implement in-house as `<ul>` of `<img>` with `filter: grayscale(1) opacity(.6)` at rest, `:hover { filter: none; transform: scale(1.08) }` on the individual `<li>`, transform/filter both compositor-friendly.
- **Perf/a11y:** Keep logo count small (≤12 unique) so the duplicated track stays light; each logo needs real `alt` text (store name), and the strip needs one `aria-label` region wrapper, same as the existing Marquee.
- **Shot:** `uiverse-marquee-full.png` (visual confirmation of the icon-row pattern, applied to social/app icons there).

### 7. Vertical marquee (column ticker)
- **Look:** Content scrolls bottom-to-top in a fixed-height column instead of left-to-right — same duplicate-content-then-translate technique, axis swapped.
- **Section:** A compact "recent" or "now shipping" column ticker beside the Now-pill, or inside the Skills ledger as a scrolling stack of tech names.
- **Sketch:** Ryan Mulligan's "Infinite Marquee" post (direct-loaded) demonstrates exactly this: same `@keyframes` but `translateY(-50%)` instead of `translateX(-50%)`, `flex-direction: column` on the track, fixed `height` + `overflow: hidden` on the wrapper, `mask-image: linear-gradient(to bottom, transparent, #000 8%, #000 92%, transparent)` (rotate the existing horizontal mask 90°).
- **Perf/a11y:** Identical cost profile to the existing horizontal marquee (still transform-only). Vertical marquees read slower/more scannable than horizontal ones by nature — good for content meant to be read, not just felt.
- **Shot:** `ddg-vertical-marquee-full.png`; source demo referenced at `ryanmulligan-css-marquee-full.png` (pass 3).

### 8. Stacked counter-rotating "logo wall" (3–4 rows)
- **Look:** Extends the existing 2-row counter-scroll to 3–4 rows, each at a different speed and (optionally) a slight row-to-row horizontal offset, so the whole block reads as a loose grid drifting apart rather than two clean lanes.
- **Section:** A denser "18 storefronts" or "tech stack" wall — directly answers the "new ways to show 18 storefronts" brief.
- **Sketch:** Same `Marquee.tsx` pattern generalized: `rows = chunk(items, items.length/N)`, each row gets a unique `animation-duration` (e.g. 40s/52s/64s/76s) and alternating `animation-direction`. No new mechanism, just N instead of 2.
- **Perf/a11y:** Cost scales linearly with row count but stays transform-only; cap at 4 rows on mobile (viewport height budget) and collapse to the existing 2-row baseline under `prefers-reduced-motion`.
- **Shot:** `ryanmulligan-css-marquee-full.png` (their logo-wall demo, pass 3).

### 9. Curved/arc marquee (draggable)
- **Look:** Text follows a shallow arc (like text wrapped around the bottom of a circle) instead of a straight line, and can be **grabbed and dragged** to manually scrub through it, resuming autoplay on release.
- **Section:** A playful accent on the "Explore themes" switcher or the FAQ header — arc shape visually says "there's more below/around."
- **Sketch:** Mirrors React Bits' `CurvedLoop` prop contract exactly (confirmed live): `marqueeText`, `speed`, `curveAmount` (px of sag), `direction: 'left'|'right'`, `interactive: boolean`. Implementation is SVG `<textPath>` on a quadratic-bezier `<path>`, with `startOffset` animated by rAF for autoplay and swapped to pointer-delta-driven for the drag state.
- **Perf/a11y:** `startOffset` animation on `<textPath>` is not compositor-accelerated (it's a layout-affecting SVG property) — throttle to one rAF tick per frame and keep the path short; provide a keyboard alternative (arrow-key nudges `startOffset`) since dragging is pointer-only.
- **Shot:** `reactbits-curved-loop-full.png` (direct capture, live demo + exact prop table).

### 10. 3D rotating text cylinder
- **Look:** Words appear to be printed around the inside (or outside) of a rotating cylinder — as one word rotates away, the next scrolls into view with real perspective foreshortening, not just a flat slide.
- **Section:** A one-off hero or Explore-themes accent for the new Persona-3-style theme, where a bold "chunky 3D" moment fits the aesthetic.
- **Sketch:** Direct source: `codeshack.io/3d-rotating-text-cylinder-css/` — N panels (one per word) placed via `transform: rotateX(<360/N * i>deg) translateZ(<radius>px)` inside a `perspective`-having parent; the whole cylinder rotates via one animated `rotateX` on the parent, so each panel's own transform stays static (cheap).
- **Perf/a11y:** `perspective` + 3D transforms are GPU-composited but pricier than 2D translate — limit to a handful of words, avoid combining with the always-on ticker's frame budget; must not autoplay for very long durations without a pause affordance, since 3D motion is more likely to trigger vestibular discomfort — hide it entirely (not just slow it) under reduced-motion.
- **Shot:** `codeshack-3d-cylinder-full.png` (pass 3, direct demo capture) + `ddg-css-marquee-3d-cylinder-full.png` (SERP context).

### 11. Velocity-driven skew tied to scroll speed
- **Look:** A large marquee headline (e.g. "React Bits React Bits…" style but with maxfolio's own words) that visibly shears/skews and speeds up in direct proportion to how fast the user is scrolling the page right now, and relaxes back to a neutral upright state the instant scrolling stops.
- **Section:** A transitional divider between two heavy sections (e.g. between Years and Process) — turns an otherwise-empty scroll stretch into a moment that responds to the user's own gesture.
- **Sketch:** Exact, reusable prop contract confirmed live on React Bits' `Scroll Velocity` component: `velocity` (base speed, sign flips per row), `numCopies`, `damping`/`stiffness` (spring), `velocityMapping: { input: [0,1000], output: [0,5] }` mapping raw scroll velocity to a skew/speed multiplier. Since maxfolio already runs Lenis, read `lenis.velocity` each `scroll` (or rAF) tick instead of a raw `window.scrollY` delta, feed it into a `framer-motion` `useSpring` (same `damping`/`stiffness` shape), and drive both `translateX` speed and a small `skewX` (±4deg cap) off the spring value.
- **Perf/a11y:** Spring-driven `translateX`/`skewX` stay transform-only and compositor-cheap even at high scroll velocity. Cap the skew angle hard (large skew reads as broken, not stylish) and clamp velocity input so a trackpad fling doesn't produce an absurd blur; disable entirely under reduced-motion (this is the single most motion-intense idea in the catalog).
- **Shot:** `reactbits-scroll-velocity-2-full.png` (direct capture, live two-row demo + full prop table); `ddg-gsap-marquee-full.png` (GSAP-side sources: `demos.gsap.com/demo/velocity-skew`, `gsapvault.com/effects/scroll-velocity-skew`, both SERP-confirmed).

### 12. Chromatic-aberration velocity smear
- **Look:** Same velocity input as #11, but instead of (or in addition to) skew, the text splits into cyan/red channel copies that separate proportionally to scroll speed and snap back together at rest — a "long-exposure photo" effect on type.
- **Section:** One dramatic accent inside the Persona-3-style theme specifically (the brief calls for "comic feel" — chromatic split reads like a printing misregistration, which fits a halftone/comic aesthetic).
- **Sketch:** Named and described precisely by GSAP Vault (`gsapvault-velocity-skew`, SERP + attempted direct load): three stacked absolutely-positioned copies of the same text, cyan/magenta/base, each offset by `translateX(velocity * k)` in opposite directions, `mix-blend-mode: screen` to recombine at rest (offset ≈0).
- **Perf/a11y:** Three text layers instead of one triples paint cost for that element only (still transform-driven, so still cheap relative to filter-based glow effects). Reduced-motion: collapse to a single static layer, no offset ever applied.
- **Shot:** `ddg-gsap-marquee-full.png`.

### 13. Masked gradient edges — upgraded to interactive width
- **Look:** The existing `mask-image` edge-fade widens/softens on hover (fade zone grows from 8%/92% to ~20%/80%), visually "opening up" the ticker as if inviting a longer look, then snaps back on mouseleave.
- **Section:** Any existing ticker — cheapest possible upgrade to the current baseline.
- **Sketch:** Animate a CSS custom property (`--mask-stop: 8%`) referenced inside the existing `mask-image` gradient string; transition the custom property via `@property` registration (`syntax: '<percentage>'`) so the browser can interpolate it directly, avoiding a JS-driven style rewrite.
- **Perf/a11y:** `mask-image` recompute on custom-property change is not GPU-free but is limited to the mask layer, not full repaint; `@property` has ~93%+ baseline support in 2026 evergreen browsers — provide a `@supports not (...)` fallback that just leaves the mask static.
- **Shot:** n/a (CSS-only mechanic).

### 14. Drag-to-scrub marquee
- **Look:** The ticker autoplays at rest; grabbing it with the mouse (or a touch drag) takes over completely — it tracks the pointer 1:1 while dragging, then on release it "throws" with momentum proportional to the release velocity before settling back into steady autoplay.
- **Section:** Gallery carousel companion strip, or the Shopify-work index if it's reframed as a browsable rail rather than a passive ticker.
- **Sketch:** Directly matches Fancy Components' "Simple Marquee" (SERP-confirmed): built on `motion`'s `useAnimationFrame` hook rather than CSS keyframes specifically so drag, momentum, and velocity-based speed can share one `x` motion value; on `pointerdown` cancel the rAF-driven autoplay increment and set `x` from `pointermove` deltas directly, on `pointerup` compute release velocity and hand off to a `framer-motion` `animate(x, target, { type: 'inertia' })` decay before resuming the steady loop.
- **Perf/a11y:** Pointer Events API handles mouse+touch uniformly; must call `setPointerCapture` so the drag survives the pointer leaving the element bounds. Add `touch-action: pan-y` so a horizontal drag doesn't fight the page's vertical scroll on mobile. Provide arrow-key nudge as the keyboard equivalent, mirroring `fwdtools.com`'s "Drag Scroll Row" a11y note.
- **Shot:** `ddg-drag-scrub-marquee-full.png`.

### 15. Sticky word-swap ticker
- **Look:** A single position holds one word/phrase that periodically swaps for the next in a short list — not a continuous scroll, but a discrete crossfade/slide-up swap on an interval (e.g. every 2.4s) — "available for: **Shopify builds** → **CRO audits** → **brand systems**".
- **Section:** Contact section CTA line, or the hero's role line ("Max Bustamante, **CTO** → **Shopify Tech Lead** → **builder**").
- **Sketch:** Not a scrolling marquee at all mechanically — a single `AnimatePresence`-wrapped `motion.span` in framer-motion, `initial={{y: 12, opacity: 0}}`, `animate={{y:0, opacity:1}}`, `exit={{y:-12, opacity:0}}`, index advanced on a `setInterval` that pauses on hover/focus and on document hidden (`visibilitychange`).
- **Perf/a11y:** Very cheap (one small element animating). Must use `aria-live="polite"` on the wrapping element so screen readers announce each swap once, not continuously, and must pause under reduced-motion (swap instantly with no transition, or slow the interval significantly) rather than disable the words entirely, since the content itself is meaningful, not decorative.
- **Shot:** n/a (compositional idea, not directly demoed on a captured page).

### 16. Text-stroke + fill sweep on hover (per-character)
- **Look:** Same idea as #5 but finer-grained — each character (not the whole word) fills in sequence left-to-right with a tiny stagger, like a highlighter dragging across the word.
- **Section:** Manifesto band pull-quote words, or a single hero word treated as a signature moment (not the whole ticker).
- **Sketch:** Split the word into `<span>` per character (a Splitting/segmenter approach — could reuse an existing text-splitting utility if maxfolio has one for other reveal animations); each span starts `color: transparent; -webkit-text-stroke: 1px currentColor`, and a `framer-motion` stagger (`staggerChildren: 0.02`) animates each to `color: <accent>; -webkit-text-stroke: 0`.
- **Perf/a11y:** Character-splitting breaks screen-reader word boundaries if done naively — wrap the split spans in a single element with the real word as `aria-label` and mark the spans `aria-hidden="true"`.
- **Shot:** `ddg-outline-fill-text-hover-full.png` (codefronts.com roundup, SERP-confirmed; names "liquid fill" and "spotlight mask" as sibling effects worth a follow-up look).

### 17. Marquee-only-on-hover (truncation reveal)
- **Look:** A long single line of text (a full store name, a long role title) sits truncated with `text-overflow: ellipsis` at rest; hovering starts a one-shot horizontal scroll that reveals the full text once, then resets — it is NOT a continuous ticker, it activates only for text that doesn't fit.
- **Section:** Shopify-work index rows on narrow layouts, or the Skills ledger where a tech name + version string might overflow a fixed-width chip.
- **Sketch:** Directly matches `github.com/arschmitz/hover-marquee` (SERP-confirmed) and the Stack Overflow answer describing "scrolls completely even if text is shorter than the space, any text length takes the same amount of time." Detect overflow via `el.scrollWidth > el.clientWidth`; only elements that actually overflow get the hover listener attached (progressive enhancement, not a blanket ticker).
- **Perf/a11y:** Essentially free — it only ever animates the specific overflowing element, on demand. This is the single most accessible entry in the catalog since it never auto-plays.
- **Shot:** `ddg-hoverdev-marquee-full.png` (SERP row for the GitHub repo).

### 18. Stock-ticker stat band
- **Look:** The existing count-up stat band restyled with literal stock-ticker visual language: monospace/tabular-nums, small colored triangles or `+`/`–` deltas next to each number, a thin scrolling strip of secondary metrics underneath the big hero numerals.
- **Section:** Stat band (hairline numerals) — a direct, literal answer to "new ways to show dense info."
- **Sketch:** `getskyscraper.com`'s tutorial (SERP-confirmed) names the exact visual grammar: `font-variant-numeric: tabular-nums`, a duplicated-content translateX strip for the secondary row, colored delta glyphs as inline `<span>` with `color: var(--up)`/`var(--down)`.
- **Perf/a11y:** Same transform-only cost as the baseline ticker. Every number must be real (per the absolute-honesty constraint) — deltas need an actual "since when" comparison basis stated in an `aria-describedby`, not just a decorative arrow.
- **Shot:** n/a (technique described in SERP text, not visually captured).

### 19. Row-clone ticker (time / drag / scroll-position modes, minimal DOM)
- **Look:** Functionally similar to the baseline, but the underlying engine can switch modes without changing markup: default autoplay-by-time, or bound to page scroll position (ticker only advances while the page scrolls, like a scrubber), or user-draggable — and it clones only as many DOM copies as the viewport actually needs (not a flat 2× duplication).
- **Section:** A shared upgrade path for ALL of maxfolio's tickers if the team ever wants one engine instead of bespoke CSS per instance.
- **Sketch:** Official reference: `motion.dev/docs/react-ticker` (direct-loaded) — a first-party 2.1kb Motion component built exactly for this ("Build infinite ticker and marquee animations in React... scrolls by time, drag or scroll position, cloning only the items it needs"). Worth evaluating as a dependency swap-in before hand-rolling modes 11/14 above from scratch.
- **Perf/a11y:** Smaller bundle (2.1kb) than hand-rolling three separate mechanisms; still needs the same reduced-motion and focus-pause wiring layered on top since it's a mechanics-only primitive.
- **Shot:** `motiondev-react-ticker-full.png` (pass 3, direct docs capture).

### 20. No-gap duplication technique, formalized as a hook
- **Look:** No new visual — this is the plumbing check. Confirms maxfolio's existing `Math.ceil` split + duplicated `<ul>` copy is already the industry-standard "no visible seam" technique, not something to replace.
- **Section:** All tickers — infrastructure note, not a new UI idea.
- **Sketch:** `effect-labs.com`'s writeup (direct-load attempt) states the technique in one line: "duplicate content + `translateX(-50%)` for a seamless loop" — exactly what `Marquee.tsx` already does. The only real upgrade available here is auto-computing how many duplicates are needed for very short item lists (today it's a flat 2×; for a 3-item list at a wide viewport, 2× might still show a gap) — measure `trackWidth < containerWidth * 2` and duplicate a 3rd time if so.
- **Perf/a11y:** No change in cost; this only prevents a rare short-list visual bug.
- **Shot:** n/a.

### 21. Momentum drag-row (non-looping sibling)
- **Look:** A horizontally scrollable row (case-study thumbnails, gallery frames) that isn't an infinite loop at all, but drags with momentum and clamps hard at both edges, with a visible fade mask only on the side that still has content.
- **Section:** Gallery carousel or Shopify-work index, as the "browse deliberately" counterpart to the passive tickers above.
- **Sketch:** `fwdtools.com/ui-snippets/drag-scroll-row/` (SERP-confirmed) describes the exact feature set: momentum gliding, edge clamping, one-sided fade masks (mask only shows on the side with more content — recompute on scroll), arrow-key support.
- **Perf/a11y:** Native `scroll-snap-type` + `overflow-x: auto` can deliver most of this with zero JS if momentum/rubber-banding from the OS is acceptable; only add custom pointer-drag math if native scroll-snap isn't enough. Arrow-key support is the a11y-critical detail most demos skip.
- **Shot:** `ddg-drag-scrub-marquee-full.png`.

### 22. Vertical "growing on approach" reel ticker
- **Look:** A vertical strip of small video/phone cards drifting upward continuously; whichever card is nearest the vertical center grows smoothly larger, then shrinks back as it passes — like items floating past a magnifying zone.
- **Section:** The Years unit chart's "phone scrubber," or a new compact gallery mode for the mobile breakpoint of the Gallery carousel.
- **Sketch:** Named directly by the Framer Marketplace "ShoppableReels" listing (SERP-confirmed): "a looping ticker of vertical video cards that grow smoothly as they pass the centre." Implement via `IntersectionObserver` with multiple thresholds against a horizontal center band, or a `framer-motion` `useTransform` mapping each card's distance-from-center (via `useScroll`/rAF-measured `getBoundingClientRect`) to a `scale` between 0.85 and 1.15.
- **Perf/a11y:** `scale` transforms stay compositor-cheap; measuring `getBoundingClientRect` every frame for many cards is the real cost — throttle to rAF and only measure cards currently within the viewport ± one card height.
- **Shot:** n/a (technique described in SERP text; no direct demo captured).

## 3. Avoid list

- **Never fully un-pausable.** Any ticker that can't be stopped by the user (hover, focus, or a visible control) fails WCAG 2.2.2 (Pause, Stop, Hide) for anything that moves >5s and starts automatically — this applies to every idea above once it's live, not just the baseline.
- **Missing keyboard/focus parity.** A hover-only pause (mouse-only) leaves keyboard users with a permanently moving element they can't stop — every `:hover` rule in this catalog must ship with a matching `:focus-within`.
- **Animating layout properties instead of transform/opacity.** Anything that changes `left`, `margin`, `width`, or non-compositable filters on every frame will jank on mid-range mobile even if it looks fine on a dev machine — stick to `transform`, `opacity`, and (carefully budgeted) `filter`/`mask-image`.
- **Marquee for anything the user actually needs to read carefully.** Reserve continuous horizontal motion for decorative/ambient content (store names, tech logos); anything the visitor must comprehend (a stat's real meaning, a CTA) should not require chasing a moving target.
- **Too many simultaneous tickers.** Stacking multiple independently-moving strips on one screen (as in idea #8 taken too far) reads as visual noise and is a recurring awards-forum criticism of over-decorated portfolios — use at most one "busy" ticker per viewport at a time.
- **3D/chromatic/skew effects that never rest.** Ideas #10–12 are the most motion-intense in this catalog; judges and forums specifically call out sites where a striking effect never lets the eye settle — always return to a calm baseline between triggers, and gate all three hard behind `prefers-reduced-motion`.
- **Drag-to-scrub without a click/drag disambiguation.** If a scrubbable row also contains clickable case-study cards, a naive pointer-down-then-move implementation will eat real clicks — require a minimum drag distance (~6-8px) before treating a pointer sequence as a drag rather than a click.
- **Decorative motion that tanks Lighthouse/TBT.** Per house convention (`lighthouse-mide-mi-cpu-no-la-tienda` in the knowledge base), measure any of these on an otherwise-idle machine — GSAP ScrollTrigger velocity listeners and rAF-driven drag/momentum code (#11, #12, #14, #22) are exactly the kind of always-listening code that inflates TBT if not gated to only run while the element is in view (`IntersectionObserver` gate on all rAF loops).
