# maxfolio.dev — synthesis menu (workflow 4)

Synthesized from 12 research digests (`wf4-*.md`, this scratchpad) covering ~180 live sites/threads and
~700 screenshots under `refs3/`. Cross-checked against `docs/research/2026-09-*.md` in the
max-folio-skills repo to confirm no site was re-visited. Context: maxfolio.dev, React 19 + Vite +
Tailwind 3 + framer-motion (LazyMotion) + Lenis, EN/ES/JA, 4 existing theme routes (Apple Clean default
/luxury /brutalist /menu). Absolute-honesty rule applies to every item below: no invented metric, no
copyrighted asset, own shapes/color/type only for the two new themes.

Legend — **Effort**: S = a sitting, M = a day, L = multi-day/needs new infra. **LH risk** = risk to
Lighthouse 100 if shipped carelessly (none/low/med — med items need the perf note in their sketch
followed exactly). Every item respects `prefers-reduced-motion` even where not restated.

## A. Ticker / marquee variants (6)

**1. Speed-up-on-hover (not pause)**
One-line: hover drops `animation-duration` ~3.3× via a CSS custom property instead of freezing the row.
Ref: `wf4-tickers.md` idea 1. Themes: Apple, Luxury, Brutalist, Neo. Effort: S. LH risk: none.
A11y: gate behind `@media (prefers-reduced-motion: no-preference)`; keep hard pause as the reduced-motion state, not speed-up.
Sketch: `--marquee-dur` custom prop read by the existing `@keyframes marquee`; `:hover`/`:focus-within` swaps it over a 300ms ease-out transition on the property itself. Zero JS, reuses `Marquee.tsx`.

**2. Reverse-direction-on-hover**
One-line: row visibly decelerates, stops, and reverses while hovered, resumes forward on leave.
Ref: `wf4-tickers.md` idea 2. Themes: Apple, Luxury. Effort: S. LH risk: none.
A11y: `@media (hover: hover)` guard so touch never triggers it; `:focus-within` parity required.
Sketch: toggle `animation-direction: reverse` via a hover class; the loop is symmetric (translateX -50%) so the reversal has no visible jump.

**3. Velocity-driven skew tied to Lenis scroll speed**
One-line: a large marquee headline shears and speeds up in proportion to live scroll velocity, relaxes when scrolling stops.
Ref: `wf4-tickers.md` idea 11 (React Bits `ScrollVelocity` prop contract confirmed live: `velocity`, `numCopies`, `damping`/`stiffness`, `velocityMapping`). Themes: Brutalist, Persona. Effort: M. LH risk: low (spring-driven transform/skew stays compositor-only, but cap skew angle hard).
A11y: fully disabled under reduced-motion — this is the single most motion-intense ticker idea in the catalog.
Sketch: read `lenis.velocity` each rAF tick, feed into a framer-motion `useSpring` (same damping/stiffness shape as React Bits), drive `translateX` speed + `skewX(±4deg cap)` off the spring value; clamp input so a trackpad fling doesn't blur.

**4. Curved/arc draggable marquee**
One-line: text follows a shallow SVG arc and can be grabbed/dragged to scrub, resuming autoplay on release.
Ref: `wf4-tickers.md` idea 9 (React Bits `CurvedLoop`: `marqueeText`, `speed`, `curveAmount`, `direction`, `interactive`). Themes: Menu (Explore-themes switcher), FAQ header accent. Effort: M. LH risk: low (`startOffset` on `<textPath>` isn't compositor-accelerated — throttle to one rAF tick, keep the path short).
A11y: arrow-key nudge as the keyboard equivalent since dragging is pointer-only.
Sketch: SVG `<textPath>` on a quadratic-bezier `<path>`; `startOffset` animated by rAF for autoplay, swapped to pointer-delta-driven on drag.

**5. Logo/image-strip marquee, grayscale→color+scale on hover**
One-line: small store/brand marks scroll continuously in low-opacity grayscale; the one under the cursor snaps to full color + 1.08× scale.
Ref: `wf4-tickers.md` idea 6. Themes: Apple (Shopify Work index "who we've built for" strip). Effort: S. LH risk: none.
A11y: real `alt` per logo (store name), one `aria-label` region wrapper matching the existing Marquee pattern.
Sketch: `<ul>` of `<img>` with `filter: grayscale(1) opacity(.6)` at rest, `:hover{filter:none; transform:scale(1.08)}` on the individual `<li>` — both compositor-friendly properties.

**6. Marquee-only-on-hover (truncation reveal)**
One-line: a truncated long line (store name, role title) scrolls once on hover to reveal itself, then resets — never auto-plays.
Ref: `wf4-tickers.md` idea 17 (matches `github.com/arschmitz/hover-marquee`). Themes: all. Effort: S. LH risk: none — only overflowing elements get a listener.
A11y: the single most accessible entry in the whole ticker catalog since it never auto-plays; still needs `:focus` parity.
Sketch: detect `el.scrollWidth > el.clientWidth`; only overflowing elements get the hover listener (progressive enhancement, not a blanket ticker). Use on Shopify Work index rows / Skills ledger chips on narrow layouts.

## B. Parallax / scroll-driven effects (7)

**7. Sticky feature-accordion scrub (AirPods pattern)**
One-line: scroll through a pinned range drives which role-pill is active while a right-column panel updates in sync — replaces hover-only with a scroll-driven equivalent.
Ref: `wf4-parallax-scroll.md` idea A1, screenshot `apple-airpods-pro-vp-1-1440.png`. Themes: Apple, Luxury. Effort: M. LH risk: low (sticky + compositor-only transforms).
A11y: DOM order = visual order, `aria-current` on the active pill; reduced-motion disables the scrub and deep-links to the last state.
Sketch: `position:sticky` wrapper (`height:100vh`) inside a taller (~300vh) container; `useScroll({target:sectionRef})` → `useTransform` rounds to an active-pill index; CSS-only fallback via `animation-timeline: view()`.

**8. CSS-only `view()`-timeline row reveals**
One-line: rows fade/slide into view purely from their own position in the viewport — zero JS, zero listeners.
Ref: `wf4-parallax-scroll.md` idea A8. Themes: all (Skills ledger, FAQ, Shopify index rows). Effort: S. LH risk: none — the cheapest win in the whole catalog.
A11y: keep `animation-range` short (entry-only) so content isn't hidden for long scroll distances; hard `prefers-reduced-motion` guard.
Sketch: `@keyframes reveal{from{opacity:0;transform:translateY(12px)}to{opacity:1;transform:none}} .row{animation:reveal linear;animation-timeline:view();animation-range:entry 0% entry 40%;}`; Motion `whileInView` fallback for Safari/Firefox until `animation-timeline` lands everywhere.

**9. Stacking cards (`position:sticky` overlap)**
One-line: a deck of cards where each new card slides up and stacks on top of the previous one, which stays pinned peeking out.
Ref: `wf4-parallax-scroll.md` idea A6, screenshot `scroll-driven-style-demos-vp-2-1440.png`. Themes: Apple (Years editorial rows, case-study chart cards). Effort: M. LH risk: none — sticky-based, no scroll listeners.
A11y: DOM order = reading order; works fine with a screen reader since it's just normal flow visually offset.
Sketch: each card `position:sticky; top:<index*24px>`, `z-index` increasing per card; optional `scale()`/`opacity` dip on the previous card via `animation-timeline: scroll()` for depth.

**10. Scroll-progress hairline bar**
One-line: a thin bar pinned to the top fills 0→100% across a long section (case-study sheet, Years chart) so the reader stays oriented — never used site-wide (forums explicitly hate a global reading-progress bar).
Ref: `wf4-parallax-scroll.md` idea A9 + `wf4-forums.md` finding #2 (AVOID: fake decorative progress bars — *"I already have scroll bars!"*, HN #40774277). Themes: all. Effort: S. LH risk: none.
A11y: purely decorative — pair with a real "Section 3 of 6" text indicator for assistive tech, never the sole wayfinding signal.
Sketch: `useScroll({target: sectionRef})` → `<motion.div style={{scaleX: scrollYProgress}} className="origin-left"/>`; scope it to ONE long section, never the whole page top.

**11. Horizontal card-rail teaser under a heading (Vision Pro pattern)**
One-line: "Take a closer look"-style heading sits above a peeking horizontal rail of preview tiles bleeding off the right edge.
Ref: `wf4-parallax-scroll.md` idea A4, screenshot `apple-vision-pro-vp-1-1440.png`. Themes: Apple (Shopify Work / Projects index "browse more" rail, especially on mobile). Effort: S. LH risk: none — native scroll-snap is browser-implemented.
A11y: real scroll container gets keyboard arrow-key scrolling and landmark nav for free; add `role="region" aria-label"`.
Sketch: `overflow-x:auto` flex row, `scroll-snap-type: x mandatory`, first/last child padding = page gutter so the bleed reads intentional.

**12. Scroll-bound path draw, formalized (Process stepper)**
One-line: the existing "self-drawing line" gets its `stroke-dashoffset`/`pathLength` bound directly to scroll progress (not a fixed duration), so draw speed matches the visitor's own scroll speed.
Ref: `wf4-parallax-scroll.md` §A + `wf4-effects.md` idea 25. Themes: all. Effort: S (formalizes something already conceptually built). LH risk: none — purely presentational, transform-only.
A11y: keep step content in normal document flow regardless of the drawn line, so screen readers get the real sequence either way.
Sketch: Motion's native `scroll()` helper bound to `pathLength`; since Lenis is in play, drive it off Lenis's own scroll value via `useMotionValue`+`useTransform` rather than the raw scroll event, so it stays in sync with the smoothed scroll.

**13. Center-focus 3D carousel with peeking neighbor slides**
One-line: gallery carousel gains real depth — the active laptop/phone frame sits large and centered, adjacent frames peek in from both edges, slightly scaled/dimmed.
Ref: `wf4-parallax-scroll.md` §A + `gsap.com/showcase` reference (GSAP showcase carousel pattern). Themes: Apple, Luxury. Effort: M. LH risk: low (transform/opacity only if done via CSS 3D, not real WebGL).
A11y: prev/next remain real buttons with visible focus rings; the "peek" is decorative, not the only navigation affordance.
Sketch: reuse the existing `src/vendor/carousel`; wrap slides in a `perspective`-having parent, animate `scale`/`opacity`/`translateX` per slide's distance-from-active via `useTransform`.

## C. New sections / new ways to show the same information (10)

Each names the **real data** it renders — nothing here is decorative-only.

**14. Radial sunburst — skill hierarchy**
One-line: center = Max, ring 1 = category (Frontend/Shopify/Platform/AI), ring 2 = individual tool; arc length = real usage frequency across the fleet.
Data: literal count of stores/repos using each tool, grepped from `package.json`/theme-settings across store repos (never invented).
Ref: `wf4-dataviz.md` idea 3, `observablehq.com/explore` sunburst thumbnail. Themes: Apple, Neo. Effort: M. LH risk: none (precomputed static SVG arcs, no d3 runtime).
A11y: each arc gets `<title>`; a visually-hidden `<table>` fallback carries the same numbers.
Sketch: precompute arc paths at build time in a small Node script (no d3 dependency shipped); `stroke-dashoffset` draw-in on scroll-into-view; replaces or augments the Skills usage ledger.

**15. GitHub-style commit-activity calendar heatmap**
One-line: a 7×N-week grid where color intensity = real commits that day across store repos — a literal receipt of "one block per shipped project."
Data: real commit dates pulled from store repo git history.
Ref: `wf4-dataviz.md` idea 4. Themes: Apple. Effort: S. LH risk: none (~1825 `<div>` cells at this scale, no canvas needed).
A11y: 5-step bucketed color (never smooth-interpolated) + a text summary ("X commits this year") for anyone who can't read the grid.
Sketch: CSS grid of divs, color via a CSS custom property bucketed into 5 steps from the existing token system; placed under Years as a hover-reveal, or beside the stat band.

**16. Streamgraph — stack/framework usage over time**
One-line: years on x-axis, flowing bands = which frameworks/tools were in active use each year, band thickness = number of stores on that stack.
Data: real per-year framework counts (React/Liquid/Remix/Tailwind versions) across ~6 years and ~5 techs.
Ref: `wf4-dataviz.md` idea 5. Themes: Apple, Neo. Effort: M. LH risk: none — precomputed static SVG, path-morph or crossfade on route enter.
A11y: pair with a hidden data table; label bands directly on hover/tap, never rely on hue alone.
Sketch: precompute smooth cubic-spline band paths at build time (tiny dataset); framer-motion `animate` on the `d` attribute, or crossfade two static SVGs if morphing proves jittery. Turns the Skills ledger into a longitudinal view.

**17. Waffle/unit chart — fleet composition census**
One-line: 18 stores as an 18-square grid, each square colored by industry category or live/DEV build-status, tappable to reveal the store + link.
Data: real per-store category + real theme role (`live`/`DEV`/in-progress) — pulls directly from the fleet state already tracked in the knowledge base.
Ref: `wf4-dataviz.md` idea 12. Themes: Apple. Effort: S. LH risk: none.
A11y: each cell is a real `<button>`; a horizontal key row underneath, never more than ~6 hues.
Sketch: CSS grid, one categorical palette; distinct from the existing Years chart (this is a single all-time census, not per-project-per-year) — a direct, honest answer to "18 storefronts, new way to show it."

**18. Numbered color-coded story cards (Pudding pattern) — Shopify Work index**
One-line: each case study gets a `#NNN` badge, a flat color field derived from that store's real dominant brand color, title + one-line dek + real ship date.
Data: real store name, real (sampled) dominant hex from the store's own screenshot, real date shipped.
Ref: `wf4-dataviz.md` idea 1, screenshot `pudding-index`. Themes: Apple. Effort: S. LH risk: none.
A11y: whole card is one `<a>`; title stays a real heading.
Sketch: 3-up desktop / 1-up mobile grid; `whileHover={{y:-4}}`, stagger children with `viewport:{once:true}` on scroll-in.

**19. Diagonal-split before/after card (Datawrapper "fix my chart" pattern)**
One-line: a real "before Digitdeck / after Digitdeck" storefront screenshot pair, clipped along a diagonal instead of a plain side-by-side.
Data: real before/after screenshots of the actual migrated storefront (Framer/WooCommerce → Shopify).
Ref: `wf4-dataviz.md` idea 7/22. Themes: Apple, Persona (reskinned as a torn-panel cut-in, item 41). Effort: S. LH risk: none (`clip-path` on two stacked images, GPU-friendly).
A11y: label chips top-left/bottom-right identify which side is which for anyone who can't perceive the visual split.
Sketch: `clip-path: polygon(...)` on two absolutely-stacked `<img>`s; optional hover-to-slide the clip percentage bound to pointer x via `useMotionValue`.

**20. Bump chart — role/stack ranking per year**
One-line: years on the x-axis, ranked lines for "primary role that year" or "most-used framework that year" crossing as rank changes.
Data: a real per-year ranking array Max already knows from his own history (role emphasis, or stack) — small enough to hand-author from real facts, never inferred.
Ref: `wf4-dataviz.md` idea 11. Themes: Apple. Effort: S. LH risk: none.
A11y: labels at line ends only (no legend clutter); each line gets a real text label, not color-only.
Sketch: SVG `<path>` per rank-line, `stroke-linecap:round`; a longitudinal companion to the Experience role rail.

**21. Dot-matrix stack map**
One-line: a grid of small dots, one per tool, positioned by two real axes (x = frontend↔backend, y = years of experience with it), sized/colored by frequency of use.
Data: real per-tool tenure + real usage-frequency counts (same source as idea 14/16 — one dataset, three visualizations).
Ref: `wf4-dataviz.md` idea 15. Themes: Apple, Neo. Effort: S. LH risk: none.
A11y: a denser, more information-honest alternative to a tag cloud — every dot has a text label on hover/focus, never hue-only.

**22. Subway-map career timeline**
One-line: a single bent, right-angle "line" running through the page, "stations" = real roles/milestones, "interchanges" = years two real things overlapped (e.g. freelance + full-time).

**23. Annual-report hero stat with nebula backdrop (Octoverse pattern)**

Data: a real number derived from actual ship dates (count of stores ÷ elapsed months) — computed, not invented, and re-derived whenever the fleet count changes (never hardcoded stale).

## D. Mobile transformations — archetype changes, not reflow (6)

**24. Nav bar → single hamburger/off-canvas sheet, labeled**
One-line: all header pills collapse into one labeled trigger opening a full-height sheet — confirmed independently on Apple, Mobbin, and Brad Frost's own site.
Ref: `wf4-mobile-transform.md` #1/#6 [shot], screenshots `apple-iphone-desktop/mobile-0.png`, `mobbin-home-desktop/mobile-0.png`, `bradfrost-responsive-desktop/mobile-0.png`. Themes: all (shared header shell). Effort: M. LH risk: none.
A11y: trigger is a real `<button aria-expanded aria-controls>`; label the trigger with the word "menu" (Brad Frost's own choice), not a bare icon — direct fix for the mystery-meat-nav anti-pattern (`wf4-forums.md` #15).
Sketch: keep desktop's per-item pill row; at `<768px` collapse ALL pills into one icon+label trigger opening a full-height `AnimatePresence` sheet (Brad Frost's "Off-Canvas" pattern, the most touch-reliable of his four); trap focus, `Escape` closes, return focus to trigger.

**25. Hero wordmark promoted: ghost-text → full-bleed lockup**
One-line: the same `<h1>` renders as small, semi-transparent background texture on desktop and as three huge, nearly-viewport-width letterforms on mobile — a role change, not a `clamp()` scale.
Ref: `wf4-mobile-transform.md` #2 [shot], `apple-iphone-desktop/mobile-0.png`. Themes: Apple (typographic hero), Persona (title card, natural fit for the diagonal cut-in). Effort: S. LH risk: none — text, zero extra weight either breakpoint.
A11y: same semantic `<h1>` both ways, only CSS treatment differs — no duplicate DOM/ARIA cost.
Sketch: two separate type treatments behind a `useMediaQuery` (not one shared `clamp()` — this is "same words, different role," not "same element scaled").

**26. Live multi-metric ticker row → vertical ledger of the same numbers**
One-line: a dense horizontal strip of real counts restacks into a vertical list on mobile, each number still individually legible — confirmed on Ramp's own live counters.
Ref: `wf4-mobile-transform.md` #8b [shot], `ramp-home-desktop/mobile-0.png` (Ramp's own real numbers quoted, e.g. "184,087" receipts processed). Themes: Apple (Skills ledger, stat band, Years count-up strip). Effort: S. LH risk: none.
A11y: `aria-live="off"` (or omit `aria-live`) — a real polling counter changing under a screen reader is disorienting noise; the final static number is what matters and must be present in the DOM at rest.
Sketch: one flex row (`flex-row flex-wrap md:flex-nowrap`) as `<dt>/<dd>` pairs; count-up via the existing stat-band `useSpring` mechanic, triggered once on `whileInView`, not looped infinitely (maxfolio has no live backend polling — a one-time honest count-up is the correct version of this pattern).

**27. Table → cards (never shrink a wide table)**
One-line: an N-column comparison table becomes one stacked card per column on mobile, row-labels repeated inside each card — never a scaled-down table.
Ref: `wf4-mobile-transform.md` #9 [pattern], reinforced by `wf4-forums.md`'s consistency-floor finding. Themes: any future before/after benchmark table in a case-study sheet. Effort: S. LH risk: none.
A11y: mobile `<dl>` needs a container `aria-label` naming what's being compared; never strip row labels to save space.
Sketch: one data source, two render paths gated by the same `useMediaQuery('(min-width:768px)')` pattern `Skills.tsx`/`Years.tsx` already use — `<table>` desktop, `<dl>`-per-item mobile.

**28. Dense layered visual → pruned to 2 elements, never scaled down**
One-line: a diagonal scatter of overlapping images (Gallery laptop/phone frame stack) crops to just 2 visible layers on mobile instead of shrinking all of them — confirmed independently on Retool, Figma, and Notion (third confirmation this pass).
Ref: `wf4-mobile-transform.md` #16b [shot], `retool-home-desktop/mobile-0.png`. Themes: Apple, Luxury (Gallery carousel). Effort: S. LH risk: none — fewer elements on mobile, not more.
A11y: cropped-away layers must not exist as hidden-but-tabbable DOM nodes — remove from the DOM at that breakpoint, not just visually hide.
Sketch: two art-directed crops (`<picture>` breakpoint swap or two separate exported layouts), never a single collage scaled by CSS.

**29. Diagonal-slash triple-bar menu glyph (Persona theme nav trigger)**
One-line: replace the expected hamburger with three parallel bars angled ~20° — a live, non-hamburger nav icon confirmed on Retool's own mobile header.
Ref: `wf4-mobile-transform.md` #10b [shot], `retool-home-mobile-0.png`. Themes: Persona. Effort: S. LH risk: none.
A11y: `aria-label="Menu"` required — the shape alone doesn't read as "menu" without it (mystery-meat-nav guard).
Sketch: three `<span>` bars, `transform: skewX(-20deg)` inside the button, no image asset — reinforces the theme's diagonal-slash identity at zero extra design cost, and doubles as item 41's motif.

## E. Theme 5 — Neumorphism / Soft UI (complete spec)

Full spec (palettes, extrusion formula, scale tokens, motion, 12 section treatments, a11y fix layer)
already fully written in `wf4-neumorphism.md` §2 — summarized here as 8 build items, each carrying its
own reference/effort/risk/a11y/sketch per the menu format, plus the section-by-section map below.

**30. Two-shadow extrusion primitive (base mechanic)**
One-line: a flat surface reads as puffed-out via a dark shadow on one diagonal + a light highlight on the opposite, 3:1 blur:distance ratio, 10–15% luminance band (past that it reads as a Windows-98 bevel).
Ref: `wf4-neumorphism.md` idea 1, `neumorphism.io` generator (exact formula: `20px 20px 60px #bebebe, -20px -20px 60px #ffffff`). Effort: S. LH risk: low (two shadows/element is cheap; don't neumorphic-ify every cell of a dense table).
A11y: n/a directly — this is the primitive every other a11y item below patches.
Sketch: `--d`(distance)/`--b`(blur)/`--r`(radius) custom properties per size token (`sm/md/lg/xl`, values in the digest §2.4); Tailwind utility classes `.soft-sm…xl` compose them.

**31. Pressed/inset universal "active" signal**
One-line: the same element with both shadows flipped `inset` reads as pushed into the page — the theme's toggle/tab/pressed-button language.
Ref: `wf4-neumorphism.md` idea 2. Effort: S. LH risk: none. A11y: must pair with a non-shadow cue (color/border/icon) — Malewicz's own named critique is "too little difference between active/pressed states."
Sketch: `[data-state="pressed"]` attribute selector swaps `box-shadow` raised→inset; real ARIA roles (`role="tablist"`, `aria-selected`) drive the swap, not vice versa.

**32. Recessed "readout" stat tiles**
One-line: stat-band numerals sit in an LCD-style sunken panel, lit from within by the accent color.
Ref: `wf4-neumorphism.md` idea 3. Effort: S. LH risk: none. A11y: count-up already reduced-motion-gated by the house pattern.
Sketch: inset extrusion + `--accent` numeral color + existing `IntersectionObserver` count-up; `font-variant-numeric: tabular-nums`.

**33. Depth-encodes-data Years chart (theme-unique)**
One-line: shipped-project tiles visibly pop forward, empty year slots sink back — depth itself carries the data, a treatment no other maxfolio theme can produce.
Ref: `wf4-neumorphism.md` idea 5. Effort: M. LH risk: none (static per-tile class). A11y: depth alone isn't perceivable non-visually — ship a text/ARIA equivalent alongside it, never depth-only.
Sketch: map `hasShippedProject(year, kind)` → raised vs inset class on the existing Years data structure — no rebuild, only the tile's shadow token changes.

**34. Analog-dial Process stepper**
One-line: an inset groove runs between numbered badges, filling with flat accent color as the user scrolls — a real analog progress dial.
Ref: `wf4-neumorphism.md` idea 6. Effort: M. LH risk: low (transform/clip-path only). A11y: reduced-motion shows the final fill state immediately, no scroll-tied animation.
Sketch: `useScroll`+`useTransform` drives a `clip-path`/`stroke-dashoffset` fill inside the inset groove; badges swap raised→inset as the fill passes.

**35. Device-bezel-as-extrusion gallery frames**
One-line: the laptop/phone frames in the Gallery carousel are literally rendered as raised soft-UI shells, screenshot living in a flat inset "screen" cutout — the most literal, on-brand use of the style.
Ref: `wf4-neumorphism.md` idea 7. Effort: S. LH risk: none — same DOM as today, only shadow/fill styling changes.
A11y: unchanged from current frame components.
Sketch: reuse the existing laptop/phone frame SVGs, swap fill/shadow to the `xl` extrusion token.

**36. Accent-fill CTA — the deliberate style break (a11y fix)**
One-line: every other interactive element is monochrome-extruded; the single primary CTA on any screen is a flat, saturated accent pill that visually wins the eye immediately.
Ref: `wf4-neumorphism.md` idea 11. Effort: S. LH risk: none. A11y: this is the direct fix for Malewicz's own "can't tell what's clickable" critique and for the "all-monochrome, zero-accent" forum/critic complaint (`refs3-awwwards.md` avoid list, item 3).
Sketch: `.cta-primary` opts OUT of the extrusion mixin entirely, flat fill + a 3px accent focus-ring offset outside the shadow.

**37. `prefers-contrast: more` flat fallback (a11y escape hatch)**
One-line: on request, every soft-UI surface instantly becomes a plain bordered card, zero shadow — shipped day one, not a follow-up.
Ref: `wf4-neumorphism.md` idea 20; independently reconfirmed by `wf4-refs3.md`'s avoid list item 3 (neumorphism's known WCAG contrast failure) and `wf4-refs3.md`/`freefrontend.com`'s note that animating `box-shadow` directly hurts INP.
Effort: S. LH risk: none — this rule REDUCES risk (it's the escape hatch). A11y: this is the theme's actual accessibility guarantee.
Sketch: `@media (prefers-contrast: more) { .soft-sm,.soft-md,.soft-lg,.soft-xl { box-shadow:none; border:1.5px solid var(--ink); } }`; never animate `box-shadow` for the raised/pressed states — crossfade layered pseudo-elements instead (compositor-friendly).

## H. A/B test implementation plan — exact files (full 22-pattern catalog in `wf4-ab-vercel.md`)

Sticky 1/3 split across three hero themes (control=Apple Clean, variant B=Neumorphism, variant C=Persona)
on Vercel, static Vite SPA, recommended as **Path A** (single bundle + inline blocking script) over
Path B (true multi-page build) unless a variant needs a genuinely separate static LCP shell.

**Files to create/edit:**
- `middleware.ts` (project root, "Other frameworks" signature — plain `Request`/`Response` Web APIs, no `next/server`) — mints/reads `mf_ab_id` + `mf_ab_bucket` cookies, calls `rewrite()` from `@vercel/functions`, sets `Vary: cookie`, excludes bots to `control`. `config.matcher: ['/']` only — never a negative-lookahead over the whole site.
- `lib/bucket.ts` — deterministic SHA-256 bucketing: hash `mf_ab_id` salted with the experiment name via Web Crypto (`crypto.subtle.digest`), never `Math.random()` (which would flip users mid-session and invalidate every metric).
- `index.html` — add the inline, synchronous, pre-`<head>` script that reads `document.cookie` and sets `document.documentElement.dataset.abTheme`, mirroring the existing "no dark-mode flash" pattern; the app's root component reads that attribute on mount to pick which theme renders at `/`.
- `api/track.ts` — Hobby-plan-compatible conversion counter (Vercel Web Analytics custom `track()` events are Pro/Enterprise-gated, confirmed live) backed by Upstash Redis's free tier via the Vercel Marketplace; called on real contact-form submission with the `bucket` field read from `dataset.abTheme`.
- `api/dashboard.ts` (or a flat authenticated HTML page) — single JSON endpoint + 3-number/1-bar minimal read view, no charting library, no new dependency.
- Global Config (renamed Edge Config) store — `{"heroThemeSplit": {"control":0.34,"soft-ui":0.33,"persona":0.33}}`, read via `@vercel/global-config`'s `get()` at sub-ms latency, as the single knob for split weights (avoids redeploying to change weights).
- `SEOHead.tsx` — pass the SAME `canonical` value regardless of A/B bucket (one-line fix); never let a variant self-canonicalize.
- `vercel.json` — keep the existing Vite-SPA catch-all rewrite for `/luxury`/`/brutalist`/`/menu`, verify it runs AFTER the middleware rewrite (Routing Middleware always runs first, but scope it so it never swallows `/_variants/**` if Path B is later adopted).

Effort: M (Path A) / L (Path B). LH risk: low if scoped correctly (middleware adds one Edge-network hop
pre-static-asset; matcher scoping keeps it to ~1 invocation per page-load, not per-asset).
A11y: n/a (routing-layer only) — but the variant markup itself inherits every a11y item from sections E/F.

**Honesty caveat carried from `wf4-ab-vercel.md` §2F**: a rare "contact request" conversion event needs

this test as a **directional signal** (scroll depth, time-on-page, gallery interaction) at 30/60/90 days,

## I. SEO / performance checklist — top 10 (full 13-item checklist with exact snippets in `wf4-seo-perf.md`)

Grounded in what the repo actually ships today (`index.html`, `SEOHead.tsx`, `LanguageContext.tsx`,
`vite.config.ts`, `robots.txt`, `sitemap.xml`, `docs/lighthouse-baseline.md` — baseline mobile 95/100/100/100,
desktop 100/100/100/100, LCP≈2.7s, TBT 60ms, CLS 0).

1. **Fix `robots.txt`'s `Sitemap:` domain mismatch** — it points at `maxfolio.co`, every canonical/OG/JSON-LD URL in `index.html` is `www.maxfolio.dev`. Zero-risk, ship regardless of anything else.
2. **Upgrade JSON-LD** from plain `Person`+`WebSite` to `ProfilePage` wrapping `Person` as `mainEntity`, add `hasOccupation` — matches Google's Profile-page rich-result shape exactly.
3. **Add one `CreativeWork`+`ImageObject` JSON-LD block per Shopify case study** — gated on each case study getting a real crawlable URL (item 5 below).
4. **hreflang has zero infrastructure today** — locale lives only in `localStorage`/`navigator.language`; cheapest fix is real `?lang=es`/`?lang=ja` query-param routes read by `LanguageContext` on mount, plus `rel=alternate hreflang` tags. Flag path-prefix (`/es/`) as the proper follow-up, not the final state.
5. **Prerender per-route/per-locale HTML** (`vite-plugin-prerender-spa` or similar) — the fix that actually makes items 3 and 4 indexable; today this is a pure CSR SPA with `SEOHead.tsx`'s meta mutation running client-side in a `useEffect`, invisible to a non-JS-executing crawler.
6. **Per-theme OG image via `@vercel/og` Edge Function** (`api/og.tsx`) — today all 4 (soon 6) theme routes share one static `og-image.png`.
7. **`content-visibility: auto` + `contain-intrinsic-size`** on Years/Gallery/Projects/Skills — web.dev's own measured 7× rendering boost on long off-screen content; must pair with an accurate intrinsic-size guess to protect the existing CLS-0 baseline.
8. **INP budget (200ms p75) for every new ticker/parallax handler** from sections A/B above — transform/opacity only, `useMotionValue`/refs not `useState`, verified in DevTools Performance on an idle machine (per house memory: *"Lighthouse mide mi CPU, no la tienda"* — never benchmark while another job is running).
9. **`prefers-reduced-motion` coverage for every new animation** (ticker, parallax, cut-in panels, halftone reveals) — a scroll-hijacked panel's hidden reduced-motion variant needs `inert`, not just `display:none`, to actually drop out of the tab/AT order.
10. **`will-change` hygiene** — apply only mid-animation, remove after; a static `will-change` left on many long-lived layers is the most common GPU-memory antipattern in animated-site postmortems, and directly conflicts with the project's stated mobile-first priority.

## J. What to avoid (forum-sourced, cross-lens — full lists per-digest in each `wf4-*.md` §3)

- **Scroll-hijacking, in any form.** The single most repeated, most viscerally worded complaint across both HN and reddit: *"If a genius can't make a tricky personal website without breaking things, what chance do normal people have? Just make a normal website."* (seagreen, HN #12804406, re: worrydream.com). Every pinned/sticky idea in section B must degrade to native scroll on any non-standard input — never fight the user's own scroll velocity or direction. (`wf4-forums.md`)
- **Loading screens / splash pages gating real content.** *"it's really just an obstacle for users who are trying to see your portfolio"* (r/web_design). Never gate the hero behind a splash/loader; any self-drawing or count-up motion runs ON the visible hero, not before it. (`wf4-forums.md`, `wf4-refs3.md`)
- **Decorative scroll-progress bars and link-hover preview popups.** *"I already have scroll bars! I do not need more scroll bars!"*; *"preview popups? Get in the sea, hostile obnoxious interruption."* (both HN #40774277). Keep item 10's progress bar scoped to one long section, paired with a real text wayfinding cue, never a global reading-progress layer. (`wf4-forums.md`)
- **Mystery-meat navigation.** A named, self-policed anti-pattern across design subreddits — every icon-only nav element (items 24, 29, 39) needs a visible/focus label, not just a shape. (`wf4-forums.md`)
- **Motion that reads as "junior dev" rather than "skilled dev."** The exact same amount of motion is praised or mocked depending on whether it demonstrates a specific ability vs. is pure page dressing — tie every florituras item above to a claim being shown. (`wf4-forums.md`)
- **Inconsistent work quality in the grid** — *"your worst work is the one that counts."* Apply a visible consistency floor to the Shopify Work and Projects indexes (item 18), not just hero pieces propping up a long tail. (`wf4-forums.md`)
- **Neumorphism's known accessibility failure mode** — monochromatic, shadow-only affordances fail WCAG contrast for low-vision users; never ship a neumorphic control whose only state signal is a shadow change (see items 31/36/37's non-negotiable pairing rules). Also: never animate `box-shadow` directly — compositor-unfriendly, hurts INP. (`wf4-neumorphism.md`, `wf4-refs3.md`)
- **Reproducing copyrighted Persona/Atlus assets, fonts, exact iconography, or proper nouns.** Every Persona item above is written as geometry/color/type technique, never traced from a game screenshot or naming a game-specific term in shipped copy — hard legal/ethical line, not a style note. (`wf4-persona.md`)
- **Style over usability (Persona theme risk).** Dense diagonal/angled chrome hurts scanability at high information density — reserve the loudest motifs (torn-panel cut-ins, skewed everything) for hero/section-break moments; keep dense content (charts, Years, Skills ledger) on a calmer grid carrying only the color/type system through. (`wf4-persona.md`)
- **Randomized/procedurally-generated scatter layouts.** Reads as AI-slop the moment placement looks `Math.random()`'d per page-load — always hand-place scatter values (item 28's crop choices, any future collage). Directly conflicts with the owner's explicit "zero AI-slop" rule. (`wf4-refs3.md`)
- **Autoplaying video/audio with no visible pause control, and cookie banners overlapping the hero.** Award-gallery critique consistently flags both. (`wf4-refs3.md`)
- **Preloaders with no progress signal or hard timeout.** A loader that never resolves reads as broken software, not craft. (`wf4-refs3.md`)
- **New runtime dependencies for a single effect.** GSAP, Three.js/WebGL, SVG-filter-heavy blob cursors — the brief is explicit that maxfolio stays on framer-motion/CSS/Lenis only; every idea above was re-sketched in-toolkit against that constraint. Approximate the *mood* (soft refraction, chromatic fringing) in cheap 2D CSS, never reach for the real shader. (`wf4-effects.md`)
- **Stacking more than 2–3 simultaneously-animating loops on one viewport.** Reads as restless, not alive — pick one "breathing" element per section. (`wf4-effects.md`, `wf4-tickers.md`)
- **Fabricated or round-number "stats."** Reinforced across every lens (dataviz, forums, copy) — every "live" or annual-report-style number in sections C/G must compute from real data or not ship.
